# 卡牌、装备与丹药词条数量及太古词条重构计划

> 状态：阶段一～四已实现并完成验证；丹药与聚灵阵的临时配置整体替换按独立计划后续实施。
>
> 本文只规划词条系统重构，不包含御剑流派本身的机制设计与落地。
>
> 本文负责卡牌、装备和丹药的词条生成、数值、打造、展示及永久被动聚合。丹药服用与聚灵阵产生的临时增益如何替换、生效和清除，统一由 `plan/exp_array_greater_affix_rework.md` 规划；本文不定义同 ID 临时被动覆盖规则。

## 1. 背景与目标

当前普通卡牌、装备和丹药共用 `GameLogic.getMinMaxExtraAffixCount`，三者最多可有 5 个额外词条，绝世卡牌与绝世装备固定有 5 个逐步解锁的额外词条。词条数量过多会削弱主词条辨识度，增加战斗阅读和打造评估成本。

本次重构采用以下单一方案：

- 普通卡牌、装备和丹药的额外词条下限始终为 0、最多 3 条，高境界随机生成也可能只有主词条，让主词条重新成为本体、额外词条成为稀有变化。
- 结丹以后不再增加槽位，改为提升已有词条的太古数量。
- 太古是已有词条的品质，不占用新槽位，不增加卡面或物品说明的文本行。
- 普通卡牌、装备和丹药的构造函数在生成全部词条后，按所属对象境界以低概率自然出现太古；卡牌灵宝、神照和混元提供低概率强化，破境使用较高概率。
- 卡牌太古词条自动锁定，默认数值为当前词条境界满级计算值的 1.5 倍；特殊数值与纯机制词条使用定制强化或禁止太古。
- 绝世卡牌与绝世装备在凝气解锁 2 个、筑基解锁 3 个固定额外词条，结丹/还婴/化神依次把三个已有词条升级为太古。
- 聚灵阵临时太古按独立计划复用同一数据模型。

### 非目标

- 不重做卡牌战斗、资源、伤害或天赋系统。
- 不实现御剑新流派内容。
- 不实现装备破境。
- 不考虑旧存档兼容与迁移（项目当前阶段明确无需兼容）。

## 2. 最终规则

### 2.1 普通卡牌、装备与丹药额外词条数量

“额外词条总数”包含普通与太古词条，太古不额外增加数量。卡牌、装备与丹药的主词条均不计入下表。

| 境界 | rank | 额外词条总数 | 其中太古上限 |
| ---- | ---: | ------------ | ------------ |
| 无   |    0 | 0～1         | 0            |
| 凝气 |    1 | 0～2         | 0            |
| 筑基 |    2 | 0～3         | 0            |
| 结丹 |    3 | 0～3         | 0～1         |
| 还婴 |    4 | 0～3         | 0～2         |
| 化神 |    5 | 0～3         | 0～3         |

随机生成的数量在对应区间内均匀抽取，高境界物品和卡牌也可能只有主词条。灵宝增加词条仍受同一个总数上限约束，太古词条也计入已有词条数。装备主动打造继续固定取额外词条上限，结丹及以上同样为 3 条，以“随机生成允许空槽、主动打造提供确定成长”区分两类路径；绝世卡牌和绝世装备仍使用固定成长列表，不参与 0 条随机。

### 2.2 太古获得方式

首期开放五类入口，分别服务随机生成、定向打造和卡牌破境成长：

1. **普通卡牌、装备与丹药的构造生成**：构造函数在全部额外词条生成后，对合格词条逐个进行低概率判定，初始概率常量建议为 5%。掉落、奖励、装备打造和炼丹都走同一构造入口；主动制作不会额外提高太古概率。rank 0～2 因太古上限为 0 而自然不会出现，rank 3～5 即使没有达到额外词条数量上限，也可在已生成的合格词条中出现太古。
2. **精炼·灵宝**：始终优先补足当前境界的词条槽位，满 3 条且达到结丹后才进行太古判定。
   - 额外词条未达到当前境界上限：100% 增加 1 条额外词条，仍受当前境界的词条池限制。
   - 额外词条已满 3 条且 rank ≥ 3：从尚未太古的合格额外词条中随机选取 1 条，进行 5% 太古判定；成功则自动锁定，未触发太古时卡牌不变。
   - 满 3 条后的灵宝操作直接按成功返回并正常消耗 1 份材料，不区分“判定成功”和“未触发太古”的结果提示；未触发太古、没有合格候选或已达到太古上限时，均可能没有实际变化。
   - 已达到当前境界上限但不足 3 条（rank < 3）：不能继续补槽也不能太古，按不可使用处理，不消耗材料。
3. **精炼·神照**：定向替换完成后，只对新生成的词条进行一次 5% 太古判定。卡牌 rank、太古上限和 `greater` 配置均满足时才可能成功；未触发时仍按普通替换成功处理。
4. **精炼·混元**：先重随主词条及所有可变、非太古词条的等级和数值，再检查当前 rank 的太古上限、已有太古数量与合格候选。若还能新增太古且存在候选，只进行一次 5% 判定；成功时从全部尚未太古且具有合法 `greater` 配置的额外词条中随机选择一条太古化，失败时仅保留数值重随结果。普通真定词条也可被选中，主词条、已有太古和无 `greater` 配置的词条不进入候选。
5. **普通卡牌打造破境**：rank +1 后保留主词条和全部已有额外词条，不再重随普通额外词条。按新 rank 重算已有词条后，若额外词条数低于新 rank 上限，进行一次 25% 新增判定，成功时从新 rank 候选池增加 1 条；随后对全部尚未太古的合格额外词条逐个进行 25% 判定，包括本次新增词条和被真定锁定的词条。

判定规则：

- 直接生成与破境在候选词条中随机顺序判定，避免固定偏向前几个槽位。
- 当前已有太古数加上新增数不能超过本境界上限，达到上限后停止。
- 没有 `greater` 配置的词条不可太古，不消耗成功次数。
- 灵宝满 3 条后的 5% 判定只选择 1 条候选，不是对整卡所有词条各判定一次；神照只判定本次新词条，混元在全体数值重随后只进行一次判定并在成功时随机选择一条候选。
- 神照生成的新词条与混元选中的普通额外词条可以太古；已有太古仍按锁定规则保护，不能成为这些操作的目标。
- 破境新增只判定一次，不按空槽数量逐个判定；达到数量上限后不再判定新增。
- 符箓复制继承原卡的太古状态与数值快照，不重新判定。

概率集中在常量中，便于后续平衡，不散落为脚本魔法数。

### 2.3 太古与锁定、破境

运行时增加两个独立标记：

- `affix.isGreater`：太古品质及展示、数值规则的真值。
- `affix.isFreezed`：卡牌打造保护标记；卡牌词条太古时自动写入 `true`，普通真定也继续写入。

本文用于太古数值计算的 rank 一律指**来源对象的 rank**：卡牌的 rank、装备或丹药的 rank，以及临时增益计划中聚灵阵的发展度 rank。词条原型上的 rank 只作为进入候选池的境界门槛，不表示词条实例拥有独立的成长境界。提取词条需要记录其来源装备的 `sourceRank`，但这不是词条自身的成长 rank。

规则如下：

- 太古只作用于额外词条，主词条不参与。
- 太古时把词条等级设为**所属卡牌、装备或丹药 rank 的满级**，随后计算太古数值；聚灵阵临时太古使用聚灵阵发展度 rank。
- 普通卡牌破境保留主词条和全部已有额外词条；卡牌达到新 rank 后，普通词条按当前等级和新 rank 重算，太古词条自动达到新境界满级并重新计算，已有太古不再次参与随机判定。
- 神照、坐忘、混元和真定选择目标时通过 `isFreezed` 自然排除太古。
- 破境不再重随普通额外词条，因此真定不再承担“防止破境换词”的必要前置作用，但仍用于保护普通词条不被神照、坐忘和混元修改；弱势普通词条的换池由混元、坐忘和灵宝负责，而不是破境。
- 普通真定的最大锁定数从 5 调整为普通卡牌额外词条上限 3；太古也计入已锁定数量。
- 装备本期不开放破境和卡牌式锁定操作，只使用 `isGreater` 表示品质；不因为装备太古而引入新的打造操作。

### 2.4 数值、纯机制词条与太古描述

禁止对所有 `value` 和机制字段统一乘以 1.5。每个词条原型通过可选 `greater` 表显式声明自己是否可太古以及如何强化：

```json5
example_default_affix: {
  // 仅对 value[0] 应用 kDefaultGreaterAffixFactor（当前 1.5）
  greater: true,
},

example_numeric_affix: {
  // 其他词条字段……
  greater: {
    values: [
      { mode: "multiply", factor: 1.5 }, // value[0]
      // 其余下标不强化
    ],
  },
},

example_count_affix: {
  greater: {
    values: [
      { mode: "add", amount: 1 }, // 观星/抽牌等次数使用加法而非乘出小数
    ],
  },
},

example_mechanism_affix: {
  greater: {
    description: "affix_example_mechanism_greater", // 可选：太古后的专用描述
    data: { scryOptions: { scryBonus: 1 } }, // 数值累加；字段不存在时写入
    alt: { scryOptions: { othersCostChange: 0 } }, // 替换指定路径的普通值
  },
},
```

规则：

- `greater: true` 是默认强化简写，仅对 `value[0]` 应用 `kDefaultGreaterAffixFactor`（当前 1.5）；只能用于具有普通数值来源的词条。
- `greater.values` 与 `valueData` 按下标对应，支持 `multiply`、`add`、`set`；缺省下标不改变数值。
- 默认强化为满级普通值 ×1.5，但只有显式配置的词条才可太古。
- 卡牌先按现有 `calculateCardAffixValue` 得出满级普通值，再应用 `greater.values`，最后沿用卡牌公式的 `floor` 取整；装备与丹药按 2.6 节先计算未取整普通贡献并应用同一配置，不在每个来源上提前取整。均不修改普通公式的基本结构。
- 本阶段太古只强化原有效果，不追加普通词条不具备的新机制。`greater.data` 用于累加数值或写入原机制尚缺的参数，`greater.alt` 只替换列出的末端字段，用于移除惩罚等替代场景；同一路径不得同时配置两者。
- 运行时从词条副本生成一次太古生效配置，先应用 `data`、再应用 `alt`，不得修改公共原型或在重算时重复累加。纯机制词条只有明确消费这些配置的脚本才可太古。
- 阈值、费用、段数、百分比、资源数量等必须逐条审查，不能因存在 `valueData` 或 `increment` 就自动缩放。
- `isFixed` 只表示不随等级缩放，不妨碍显式配置的太古倍率。
- `greater.description` 为可选本地化键。移除惩罚或普通文案无法表达的机制参数变化需要改变文案时，在 `isGreater` 后替换普通 `description`；未配置时沿用普通描述。普通状态不能提前展示太古效果。装备与丹药的标量 `value` 固定使用 `greater.values` 下标 0 的配置。

### 2.5 主词条角色

卡牌、装备与丹药统一采用“主词条决定本体，额外词条提供变化；太古只是额外词条的品质”的解释。卡牌主词条承载流派、费用、类别等卡牌信息；装备与丹药的 `affixes` 首条按主词条处理，后续词条才是额外词条。不要求统一三者的原型数据结构，只统一主/额外词条的运行时角色和太古规则。

主词条不参与太古：不写入 `isGreater`，不占用太古数量上限，不自动锁定，不显示 `✶` 或黄色太古样式，也不使用 `greater.values`、`greater.data` 或 `greater.description`。化神绝世卡牌与装备的完整成长统一描述为“全部额外词条均为太古”，不要求主词条太古化。

装备与丹药存在同一被动原型既可担任主词条、又可担任额外词条的情况。主词条和普通额外词条均按各自当前等级使用普通被动公式，不因为原型配置了 `greater` 而在主词条上预先应用数值强化。太古额外词条可以强于同名主词条，因为太古表示额外词条的稀有品质，不改变主词条的本体身份。

是否需要为主词条单独提供固有基础强度，暂不在本次实施中确定；备选设计记录于 `plan/main_affix_value_design.md`，后续审核后再决定是否引入独立的 `main` 数值配置。该设计不得复用 `greater` 作为隐式主词条加成。

### 2.6 被动数值、多来源聚合与 `maxLevel` 移除

被动词条彻底移除 `maxLevel` 写法与封顶语义。`calculatePassiveAffixValue` 保持 `base + increment × level` 的普通公式，不再接收或处理 `maxLevel`；原型、`PassiveData`、`characterSetPassive`、天赋树预览及其他调用方同步删除封顶逻辑。等级只由实际来源和太古规则决定，不再另设被动等级上限。

装备、天赋等永久被动采用**逐来源计算未取整贡献，再按被动 ID 汇总**的模型：

1. 每个来源记录稳定的 `sourceKey`（装备 UID＋词条位置、天赋节点 ID 等）、有效等级、未取整普通贡献、太古修正、`isGreater`、`greater` 配置及机制字段。卸下装备或退天赋时按 `sourceKey` 移除对应贡献，不再以负等级反推最终值。
2. 普通来源（包括主词条与普通额外词条）按 `base + increment × level` 得到未取整普通贡献；只有额外词条太古在对应来源上应用 `greater.values`。`set` 也只转换当前来源，转换后的贡献继续与其他来源相加。
3. 同一被动 ID 在 `passives` 中的全部未取整贡献相加后，统一 `round` 一次得到最终 `value`。不得对每个来源分别调用现有取整函数后再相加，避免小数增量产生不同结果。合计 `level` 只用于展示，不再用于反推最终数值。
4. `passives` 与 `ephemeralPassives` 继续分组聚合，因为部分属性采用“基础值 × 永久被动倍率 × 临时被动倍率”，不能跨组无差别求和。不同被动 ID 流入同一属性时，保持按被动 ID 取整后再进入属性公式的口径。
5. `battleStatus` 需要 `value` 作为状态层数时读取汇总后的最终值。`deckCostReduction`、`shuffleIntoDeck`、`turnStartScry`、`turnStartExtraDraw`、`energyRetain`、`statsBonus` 等机制字段不做统一数值相加，继续按各自契约聚合；`greater.data` 只在对应来源 `isGreater == true` 时参与。
6. 只检查被动 ID 是否存在、没有数值或机制内容的词条不受该模型影响，也不因此获得太古资格。当前被动数据均可纳入上述数值或专门机制聚合路径。

## 3. 绝世卡牌规则与数据迁移

### 3.1 新的固定成长结构

绝世卡牌最多有 3 个固定额外词条，固定额外词条数量为 `min(rank + 1, 3)`。凝气与筑基依次解锁词条1～3，结丹、还婴、化神不再增加词条，而是按 `greaterAffixes` 的顺序各将一个已解锁词条太古化：

| 境界 | rank | 固定额外词条数 | 固定太古数 |
| ---- | ---: | -------------: | ---------: |
| 凝气 |    1 |              2 |          0 |
| 筑基 |    2 |              3 |          0 |
| 结丹 |    3 |              3 |          1 |
| 还婴 |    4 |              3 |          2 |
| 化神 |    5 |              3 |          3 |

在主词条增加：

```json5
greaterAffixes: [
  { rank: 3, affixId: "example_affix_1" },
  { rank: 4, affixId: "example_affix_2" },
  { rank: 5, affixId: "example_affix_3" },
],
```

目标词条必须已经包含在该卡的 `affixes` 中，在对应境界已经解锁，并且自身具有合法 `greater` 配置。直接生成高境界绝世卡时，也要一次性应用所有已到达境界的固定太古成长。

普通随机词条允许没有 `greater` 配置，但**所有被绝世卡牌保留的固定额外词条必须统一提供太古版本**，使三个词条在化神时都能完成一次品质成长。

### 3.2 现有悟道绝世卡牌迁移

修改 `assets/data/cards.json5` 中所有带 5 个固定额外词条的绝世卡，包括五张常规绝世卡、紫微斗数和万法归宗。

这里的“去掉”指从该卡的固定成长列表移除，不一定删除词条 ID 或机制。优先保留并强化有辨识度的原有效果；重复抽牌、通用护甲等不再占用固定槽位，已移除的效果不并入其他词条的太古。仍被其他卡或随机池使用的词条继续保留，只为旧固定列表服务且已淘汰的词条，在确认无引用后移除。

以下统一按固定列表顺序称为词条1、词条2、词条3，不再为各词条额外使用标题。每张卡按 rank 3、4、5 列出三个词条各自的太古版本。

#### 天机术 `spellcraft_scry_draw`

- **保留 3 条**：词条1使未选牌费用 +1；词条2使选中牌升级；词条3使本次观星额外查看 1 张。
- **rank 3 太古**：词条3变为“本次观星额外查看 2 张”。
- **rank 4 太古**：词条2变为“选中牌由升 1 级提高至升 2 级”，不再追加减费。
- **rank 5 太古**：词条1使未选牌费用由 +1 提高至 +0，也就是移除原本的负面效果。

#### 相生相克 `spellcraft_ailments_by_used_elements`

## 4. 装备规则与悟道绝世装备迁移

### 4.1 普通装备

- 普通装备使用与卡牌相同的 2.1 数量表，额外词条最多 3 条。
- 掉落、奖励和装备打造在生成全部词条后进行低概率太古判定，已有太古数量不能超过当前境界上限。
- 普通装备的太古数值按普通被动公式得出未取整普通贡献，再应用 `greater.values`，按 2.6 节汇总取整；纯机制词条仍需要明确的 `greater.data` 消费方。
- 普通装备主词条按 2.5 节处理：在当前等级下使用普通被动公式，不应用 `greater.values`，也不获得太古品质或满级规则。
- 装备打造继续固定取当前境界额外词条上限，结丹及以上为 3 条；`ExtractedAffix` 填槽不能超过该上限。
- 精炼允许提取额外太古词条，并完整保留其 `isGreater`、来源装备的 `sourceRank`、有效等级、`greater` 配置和数值快照。已有太古填入新装备时不重新判定。
- 填入 `ExtractedAffix` 时，`sourceRank` 不得高于目标装备 rank，已有太古计入目标装备当前境界太古上限；不满足任一条件则不能填入。普通提取词条可以参与目标装备完成后的低概率太古判定。
- 装备估价继续使用现有公共数量函数，并随其新规则改为最多按 3 条额外词条估算，避免仍按旧 5 条上限计算。
- 本期不开放装备破境，也不要求普通装备的全部随机词条都支持太古。

### 4.2 绝世装备固定成长

绝世装备与绝世卡牌采用相同的“两次固定解锁 + 三次固定太古”结构：

- `items.json5` 的 `affixes` 首条仍为装备主词条，不计入 3 条额外词条上限。
- 主词条之后最多保留 3 个固定额外词条，数量为 `min(rank + 1, 3)`；rank 1 解锁词条1～2，rank 2 解锁词条1～3。
- 在物品 prototype 上增加 `greaterAffixes`，rank 3～5 依次将三个已有额外词条太古化。
- 直接生成高境界绝世装备时，一次性应用所有已到达境界的固定太古成长。
- 所有被绝世装备保留的固定额外词条必须统一提供 `greater` 配置。
- 绝世装备的太古不设置卡牌打造保护语义；本期只处理品质、数值、机制与展示。

6. 物品描述 `buildItemHoverInfo` 复用 `kAffixLeading2` 与黄色样式，展示普通装备、绝世装备与丹药的太古额外词条；主词条始终保持普通主词条样式且不显示 `✶`。

### 5.7 数据校验

涉及：`utils/data_validate/game_data_validate.dart`

新增校验：

- `greater` 只能为表，且至少含 `values`、`data` 或 `alt` 之一，`description` 为可选附加字段。只有 `description` 而没有数值或机制变化属于校验错误，该词条不得进入随机太古候选，也不得作为绝世固定太古目标。
- `values` 只能是 `multiply/add/set`，数值字段合法；有配置时下标不得超出 `valueData` 范围，装备与丹药的标量 `value` 只接受下标 0 的配置。
- `data` 与 `alt` 的字段路径必须属于已登记、确有消费方的契约；同一路径不得同时出现，`alt` 只能替换既有机制数据，不得借其新增普通词条不具备的效果类型。
- 被动原型及运行时数据不再出现 `maxLevel`；校验发现该字段时给出错误，避免重新引入封顶语义。
- 无 `valueData` 的卡牌词条不得配置 `greater.values`；无普通数值来源的装备与丹药词条同样不得配置。
- 同时允许担任装备或丹药主/额外词条的共享原型可以配置 `greater.values`；校验不得因其具有主词条用途而误判，但运行时只有真正的太古额外词条可以消费 `greater.values`、`greater.data`、`greater.alt` 与 `greater.description`。
- `greater.description` 必须存在对应本地化键。
- `greaterAffixes` 的 rank 只能为 3～5、顺序合法、目标不重复，目标必须存在于本卡或本装备的 `affixes` 中、在对应境界已经解锁，并且目标存在合法 `greater`。
- 普通随机词条的 `greater.data` 与 `greater.alt` 必须属于已登记、确有脚本消费方的契约字段，避免“看似能太古但实际无效果”。
- 绝世卡牌固定额外词条与绝世装备主词条后的固定额外词条均不超过 3 条；无对应成长的纯机制词条给出错误或明确警告。

## 7. 测试计划

项目已有测试，新增 `test/card_affix_test.dart`，并复用现有 Hetu 测试方式覆盖真实脚本路径。装备生成与固定成长可复用同一测试文件或按现有测试组织方式拆分。

### 公式与数量

- rank 0～5 的 `minExtra/maxExtra/maxGreater` 与表格完全一致，所有境界 `minExtra == 0`，现有公共函数的签名与返回结构不变。
- 普通卡牌、装备与丹药各境界额外词条总数不超过 3，高境界随机生成允许只有主词条，太古不会增加槽位，装备估价同步使用新数量；主动打造装备仍固定取当前境界上限。

### 太古数值与被动聚合

- 普通数值先按满级计算，再 ×1.5；不重复乘境界倍率。卡牌最终沿用 `floor`，装备与丹药按被动 ID 汇总未取整贡献后统一 `round` 一次。
- `add/set` 和未配置下标行为正确；装备与丹药标量 `value` 只读取下标 0。
- `data` 只累加一次，`alt` 只替换指定末端字段；同一路径冲突、公共原型被修改或重算时重复累加均应被测试阻止，太古不会追加普通词条不具备的新机制。
- 无 `greater` 配置、纯机制未消费配置的词条不会成为太古；只有 `greater.description` 的词条产生校验错误。
- 固定数值、次数和百分比只按各自配置变化，太古强化均只应用一次。
- 共享被动作为装备或丹药主词条时，按当前等级计算未取整普通贡献，不应用 `greater.values`，不设为满级，不写入 `isGreater`，也不消费 `greater.data`、`greater.alt` 或 `greater.description`。
- 同一共享被动作为普通额外词条时同样不提前应用太古强化，只有太古化后才按物品 rank 满级规则强化。
- 被动数据及所有计算路径不再存在 `maxLevel` 封顶；`start_battle_with_buff_ward` 使用 `increment: 0.05` 时，等级 100 的最终普通值为 5。
- 两个 `increment: 0.5, level: 1` 的普通同 ID 来源合计为 1，验证逐来源不提前取整。
- 同 ID 的普通主词条、普通额外与太古额外来源分别计算贡献并正确汇总；卸下装备或退点只移除对应 `sourceKey`。
- `passives` 与 `ephemeralPassives` 分组及 `battleStatus` 最终层数正确，机制字段不被误当作普通数值求和；`battleStatusParams` 的数值累加、布尔合并、普通默认值与 `addStatusEffect(params:)` 透传正确。
- `getDeckMinSizeForRank` 在普通与太古减益下均遵守独立绝对下限，不再被基准牌库大小提前截断。

### 生成、打造与精炼

- 普通卡牌、装备与丹药构造函数在全部词条生成后使用 5% 太古判定，rank 0～2 不出现太古，rank 3～5 可在任何合法额外词条数量下出现太古。
- 灵宝满 3 条后使用单条候选 5%，神照只对本次新词条使用 5%，混元在全体重随后只进行一次 5% 判定，破境新增词条和已有词条太古分别使用 25%，判定均不超过当前数量与太古上限。
- 灵宝优先补至当前境界上限，不会超过 rank 0～2 的 1/2/3 条上限；满 3 条且结丹后直接按成功返回并消耗材料，未触发太古时没有额外失败提示。
- 已达到当前境界上限但未达结丹时不可使用灵宝且不消耗材料。
- 神照在结丹后仍调用内部补槽 helper，不会误入灵宝分支；神照和混元不会触发整卡其他普通词条的太古判定，混元判定失败时仍保留全体数值重随结果。
- 候选随机顺序与上限正确，无合格词条时不产生太古；混元成功时只随机选择一条非太古合格额外词条，普通真定候选也可被选中。
- 太古自动锁定；神照、坐忘、混元不会替换、删除或重随已有太古，但神照新词条与混元选中的普通词条可以按规则成为太古。
- 卡牌破境保留主词条和全部已有额外词条，词条 ID 与数量不会减少；普通词条按新 rank 重算，太古在新 rank 下自动满级重算且不重复判定。
- 破境只在存在空槽时进行一次 25% 新增判定，达到上限时不判定新增；新增词条来自新 rank 候选池，并可参与本次后续太古判定。
- 灵宝补槽不能超过 3 条，真定锁定总数不能超过 3 条。
- 符箓继承太古快照，不重新判定。
- 普通装备与丹药的生成、掉落和制作均不超过 3 条，并按对应构造入口进行太古判定；主词条不会被纳入随机太古候选，主动打造装备仍固定取当前境界额外词条上限。
- 提取太古额外词条完整保留品质、有效等级和数值快照；填入时校验目标 rank 与太古上限，已有太古不重新判定，普通提取词条仍可参与打造后的低概率判定。

### 绝世卡牌与绝世装备

- rank 1～2 正确解锁固定额外词条，任何境界都不超过 3 条。
- rank 3～5 只增加指定太古，不新增第 4 条；化神时全部固定额外词条均为太古，主词条保持非太古。
- 绝世卡牌逐境破境与直接生成高境界卡牌的结果一致；绝世装备按不同 rank 直接生成时，均正确应用已到达境界的固定太古成长。
- 现有悟道绝世卡牌与五件悟道绝世装备全部通过引用、本地化与固定成长测试。

### 展示与战斗

- 卡面与物品悬浮提示在太古额外词条前显示 `✶`，不增加额外机制行；主词条不显示太古标识。
- 配置 `greater.description` 的词条只在太古后显示对应的惩罚移除或机制参数变化，普通状态描述不变；随机 2 张保留不重复，观星选中牌连续升 2 级只按配置执行。
- 战斗预测和实际 `takeDamage` 使用同一份太古最终值。
- 多段、固定次数、观星/抽牌等定制效果只触发一次，不与普通值重复叠加。
- 装备穿脱和被动重算后，主词条普通数值、额外词条太古数值与机制均正确生效；丹药生成的太古词条快照能够完整交给第二份计划的临时配置替换流程。
