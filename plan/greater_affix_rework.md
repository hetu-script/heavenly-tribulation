# 卡牌词条数量与太古词条重构计划

> 本文只规划词条系统重构，不包含御剑流派本身的机制设计与落地。

## 1. 背景与目标

当前普通卡牌、装备和丹药共用 `GameLogic.getMinMaxExtraAffixCount`，普通卡最多可有 5 个额外词条，绝世卡固定有 5 个逐步解锁的额外词条。词条数量过多会削弱主词条辨识度，增加战斗阅读和打造评估成本。

本次重构采用以下单一方案：

- 普通卡保留额外词条数量随机性，但最多 3 条。
- 金丹以后不再增加槽位，改为提升已有词条的太古数量。
- 太古是已有词条的品质，不占用新槽位，不增加卡面文本行。
- 直接生成卡牌低概率出现太古；灵宝金丹后提供低概率定向强化，打造破境使用较高概率。
- 太古词条自动锁定，默认数值为当前词条境界满级计算值的 1.5 倍；特殊数值与纯机制词条使用定制强化或禁止太古。
- 绝世卡前三境解锁最多 3 个固定额外词条，后两境把指定已有词条升级为太古。
- 装备、丹药本期不修改词条数量和生成概率；其太古扩展复用同一数据模型，待装备数量规则单独确定后再接入。

### 非目标

- 不重做卡牌战斗、资源、伤害或天赋系统。
- 不实现御剑新流派内容。
- 不修改普通装备、绝世装备、丹药的词条数量上下限。
- 不实现装备破境，不强制所有装备词条都能太古。
- 不考虑旧存档兼容与迁移（项目当前阶段明确无需兼容）。

## 2. 最终规则

### 2.1 普通卡额外词条数量

“额外词条总数”包含普通与太古词条，太古不额外增加数量。

| 境界 | rank | 额外词条总数 | 其中太古上限 |
| --- | ---: | --- | --- |
| 无 | 0 | 0～1 | 0 |
| 凝气 | 1 | 1～2 | 0 |
| 筑基 | 2 | 2～3 | 0 |
| 金丹（现有数据亦称结丹） | 3 | 3 | 0～1 |
| 元婴（现有数据亦称还婴） | 4 | 3 | 0～2 |
| 化神 | 5 | 3 | 0～3 |

灵宝增加词条仍受同一个总数上限约束，太古词条也计入已有词条数。

### 2.2 太古获得方式

首期开放三个入口，分别服务刷取、定向打造和破境成长：

1. **直接生成普通卡**：全部额外词条生成后，对合格词条逐个进行低概率判定，初始概率常量建议为 5%。
2. **精炼·灵宝**：金丹前保持原有补槽用途；金丹后改为低概率强化已有词条。
   - rank < 3：若未达当前上限，100% 增加 1 条额外词条，仍受 2.1 数量限制。
   - rank ≥ 3：不再增加词条，每次使用消耗 1 份材料，从尚未太古的合格额外词条中随机选取 1 条，进行 5% 太古判定；失败不修改词条并给出失败提示，成功则自动锁定。没有合格候选时不可使用且不消耗材料。
3. **普通卡打造破境**：破境、保留/重随词条全部完成后，对全部尚未太古的合格额外词条逐个进行 25% 判定，包括被真定锁定但本次也重随数值的词条。

判定规则：

- 直接生成与破境在候选词条中随机顺序判定，避免固定偏向前几个槽位。
- 当前已有太古数加上新增数不能超过本境界上限，达到上限后停止。
- 没有 `greater` 配置的词条不可太古，不消耗成功次数。
- 灵宝金丹后的 5% 判定只选择 1 条候选，不是对整卡所有词条各判定一次。
- 神照、混元不额外进行太古判定；已有太古按锁定规则保护。
- 符箓复制继承原卡的太古状态与数值快照，不重新判定。

概率集中在常量中，便于后续平衡，不散落为脚本魔法数。

### 2.3 太古与锁定、破境

运行时增加两个独立标记：

- `affix.isGreater`：太古品质及展示、数值规则的真值。
- `affix.isFreezed`：打造保护标记；太古时自动写入 `true`，普通真定也继续写入。

规则如下：

- 太古只作用于额外词条，主词条不参与。
- 太古时把词条等级设为**该词条自身 rank 的满级**，随后计算太古数值。
- 普通破境保留全部太古词条；破境同步词条 rank 后，太古自动达到新境界满级并重新计算，不再次判定该词条。
- 神照、坐忘、混元和真定选择目标时通过 `isFreezed` 自然排除太古。
- 普通卡破境仍只保留主词条、真定词条和太古词条，其余重随；由于太古自带锁定，可复用现有保留通道。
- 普通真定的最大锁定数从 5 调整为普通卡额外词条上限 3；太古也计入已锁定数量。

### 2.4 数值与纯机制词条

禁止对所有 `value` 和机制字段统一乘以 1.5。每个词条原型通过可选 `greater` 表显式声明自己是否可太古以及如何强化：

```json5
example_numeric_affix: {
  // 其他词条字段……
  greater: {
    values: [
      { mode: "multiply", factor: 1.5 }, // value[0]
      // 其余下标不强化
    ],
  },
},

example_count_affix: {
  greater: {
    values: [
      { mode: "add", amount: 1 }, // 观星/抽牌等次数使用加法而非乘出小数
    ],
  },
},

example_mechanism_affix: {
  greater: {
    data: { scryBonus: 1 }, // 由对应脚本在 isGreater 时读取
  },
},
```

规则：

- `greater.values` 与 `valueData` 按下标对应，支持 `multiply`、`add`、`set`；缺省下标不改变数值。
- 默认强化为满级普通值 ×1.5，但只有显式配置的词条才可太古。
- 卡牌先按现有 `calculateCardAffixValue` 得出满级普通值，再应用 `greater.values`；不修改普通卡牌公式。
- 纯机制词条没有统一默认效果。只有脚本明确消费 `greater.data` 时才提供对应强化；否则该词条不可太古。
- 阈值、费用、段数、百分比、资源数量等必须逐条审查，不能因存在 `valueData` 就自动缩放。
- `isFixed` 只表示不随等级缩放，不妨碍显式配置的太古倍率。

## 3. 绝世卡规则与数据迁移

### 3.1 新的固定成长结构

绝世卡同样最多 3 个固定额外词条：

- rank 1～3：按 `affixes` 列表依次解锁第 1～3 条。
- rank 4～5：不再增加词条，按主词条的 `greaterAffixes` 配置将指定已有词条太古化。

建议在主词条增加：

```json5
greaterAffixes: [
  { rank: 4, affixId: "example_affix_1" },
  { rank: 5, affixId: "example_affix_2" },
],
```

目标词条必须已经包含在该卡的 `affixes` 中，并且自身具有合法 `greater` 配置。直接生成高境界绝世卡时，也要一次性应用所有已到达境界的固定太古成长。

### 3.2 现有悟道内容迁移

修改 `assets/data/cards.json5` 中所有带 5 个固定额外词条的绝世卡，包括五张常规绝世卡、紫微斗数和万法归宗。

这里的“去掉”指从该卡的固定成长列表移除，不一定删除词条 ID 或机制。优先把有辨识度的效果合并为已有词条的太古强化；重复抽牌、通用护甲等不再占用固定槽位。仍被其他卡或随机池使用的词条继续保留，只为旧固定列表服务且已合并/淘汰的词条，在确认无引用后移除。

推荐逐张采用以下迁移方案：

#### 天机术 `spellcraft_scry_draw`

- **保留 3 条**：余星蒙尘（未选牌 +1 费）、摘星（选中牌升级）、窥天机（额外观星 2 张）。分别保留代价、规划修正和观星深度，职责最清楚。
- **rank 4 太古**：摘星吸收星引，变为“选中牌升级且费用 -1”。
- **rank 5 太古**：窥天机吸收星驻，变为“额外观星 2 张，选中牌获得保留”。
- **从固定列表去掉**：星引、星驻，效果均合并，不直接淘汰机制。

#### 相生相克 `spellcraft_ailments_by_used_elements`

- **保留 3 条**：五行相激（按已用元素增加异常层数）、化浊为清（清自异常并抽牌）、以毒攻毒（异常种数转灵气）。保留主效果放大、节流阀和资源引擎。
- **rank 4 太古**：以毒攻毒吸收以厄为铠，在异常种数达标时同时按自身异常层数获得护甲。
- **rank 5 太古**：五行相激提高每种的层数加成，突出主卡特色。
- **从固定列表去掉**：以厄为铠改为合并；处变不惊直接去掉，其“异常种数达标抽牌”与化浊为清的抽牌和节奏重复。

#### 一气化三清 `spellcraft_element_amplify`

- **保留 3 条**：元素亲和（所选元素手牌减费）、灵气共鸣（按灵气提高自身增幅）、三清护体（降低所选元素伤害）。保留当回合规划、自我强化和对称代价的对冲。
- **rank 4 太古**：灵气共鸣吸收借力导气；对手使用所选元素后，下回合获得灵气，继续喂给共鸣。
- **rank 5 太古**：三清护体吸收灵台守一，在持续减伤外增加一次性护盾。
- **从固定列表去掉**：借力导气、灵台守一，均合并；灵台守一不再与三清护体重复占槽。

#### 蓄灵诀 `spellcraft_ailments_to_mana`

- **保留 3 条**：纳气之后（获得灵气转护甲）、灵气回响（获得灵气后悟道手牌减费）、反噬成道（延迟自伤换下回合爆发）。保留防御出口、费用出口和标志性风险回报。
- **rank 4 太古**：灵气回响吸收七情归一；自身异常种数达到 5 时额外获得太极之气。
- **rank 5 太古**：反噬成道提高下回合首张悟道牌增伤，自伤规则不变。
- **从固定列表去掉**：化浊为清直接去掉，避免与相生相克共用同一节流效果；七情归一改为合并。

#### 太上忘情 `spellcraft_handcards_to_mana`

- **保留 3 条**：舍念（降低每张手牌自伤）、静心（提高每张手牌产灵）、藏锋（随机悟道手牌保留）。全部直接服务手牌数引擎。
- **rank 4 太古**：藏锋吸收忘我，保留布局同时强化下回合首张悟道牌。
- **rank 5 太古**：舍念吸收无情，在减伤之外按手牌数提供护甲。
- **从固定列表去掉**：忘我、无情，均合并；通用护甲不再单独占据核心槽位。

#### 紫微斗数 `spellcraft_draw_cards_reduce_cost`

- **保留 3 条**：定星（抽到的牌升级）、星移（抽到悟道牌获得灵气）、逆天改命（未抽到悟道牌时额外抽牌）。保留定向强化和两种抽取结果的不同回报。
- **rank 4 太古**：定星吸收留命，抽到的牌同时升级并获得保留。
- **rank 5 太古**：星移将抽到悟道牌时的灵气获得量由 1 提高至 2；不让逆天改命额外抽到的牌免费，避免免费牌循环。
- **从固定列表去掉**：通用 `defend` 直接去掉；留命改为合并。

#### 万法归宗 `spellcraft_ultimate_spell`

- **保留 3 条**：落雷击顶（超额支付施加感电并促成转化）、一法破万法（按本回合元素种数增伤）、归宗之后（抽牌减费但获得逆灵之气）。保留即时转化、元素构筑上限和爆发后的代价。
- **rank 4 太古**：落雷击顶吸收万法余波，超额支付同时按量获得护甲。
- **rank 5 太古**：一法破万法吸收雷行九霄，在元素种数增伤外，若对手打出前已有感电再获得增伤。
- **从固定列表去掉**：万法余波、雷行九霄，均合并。

迁移时同步更新 `plan/skill_tree/spellcraft.md`、`docs/docs/how2play/rpg/cultivation/genre/spellcraft.md` 与相关本地化描述，确保不再写成第 4、5 境继续新增词条。没有固定额外词条列表的通用绝世卡不受数量迁移影响，主词条仍不参与太古。

### 3.3 绝世装备的处理

本期不改变绝世装备“主词条 + rank 个固定额外词条”的解锁结构，也不强制其压缩为 3 条。

`passives.json5` 后续若启用太古，可复用与卡牌相同的 `greater` 配置：数值词条按装备公式计算后强化，纯机制词条使用定制 `greater.data` 或禁止太古。装备是否直接生成太古、是否压缩数量、绝世装备第 4/5 次成长是否改为太古化，另行评审，不与本次卡牌改动绑定。

## 4. 代码修改范围

### 4.1 数量规则与常量

- `scripts/main/binding/constants.ht`
- `lib/logic/logic.dart`
- `lib/app.dart`

步骤：

1. 增加普通卡额外词条上限、直接生成/灵宝/破境太古概率、默认太古倍率常量，并完成 Dart → Hetu 导出。
2. 新增 `GameLogic.getMinMaxBattleCardAffixCount(rank)`，返回 `minExtra/maxExtra/minGreater/maxGreater`，实现 2.1 表格。

4. 保留现有 `getMinMaxExtraAffixCount` 给装备、丹药和装备估价使用，避免误改其数量规则。

### 4.2 普通卡生成与打造

主要文件：`scripts/main/cardgame/card.ht`

步骤：

1. 将 `_addExtraAffixes` 与灵宝补槽的数量读取切换到新普通卡数量函数。
2. 抽取统一的词条数值重算函数，在现有普通值计算后应用 `greater.values`，避免在主公式中隐式处理太古。
3. 增加 `_rollGreaterAffixes(card, chance)` 与 `_markAffixGreater(card, affix)`：
   - 只遍历额外、未太古且带 `greater` 配置的词条；
   - 受 `maxGreater` 限制；
   - 写入 `isGreater/isFreezed`；
   - 设为词条自身 rank 满级并重算。
4. 普通卡构造完成全部额外词条后，以直接生成概率执行一次统一判定。
5. 拆分灵宝的内部补槽 helper 与公开 `addAffix` 操作：公开操作按卡牌 rank 执行“金丹前 100% 补槽 / 金丹后单条候选 5% 太古”，`replaceAffix` 继续调用内部补槽 helper，避免金丹后的替换操作误入太古分支。
6. `upgradeRank` 先完成境界、保留词条、重随和补槽，再以 25% 对整卡未太古候选统一判定；已有太古只按新 rank 满级重算，不重复随机。
7. `_randomizeAffixLevel` 对已有太古不再随机等级，而是固定到当前词条 rank 满级。
8. 神照、坐忘、混元、真定继续按 `isFreezed` 过滤；神照新增的普通词条不单独进行高概率判定。
9. 真定数量上限改用普通卡额外词条上限常量。

### 4.3 绝世卡固定成长

涉及：

- `scripts/main/cardgame/card.ht` 的 `_addPredefinedAffixes`、`upgradeRank`
- `assets/data/cards.json5`
- `assets/data/card_affixes.json5`

步骤：

1. 固定词条解锁数量限制为最多 3 条。
2. 固定词条处理后调用固定太古成长函数，按 `greaterAffixes` 应用 rank 已达成的目标。
3. 破境时保留已有太古并重新计算，再补上下一条固定词条或固定太古成长。
4. 为允许太古的普通随机词条和绝世固定词条补充 `greater` 配置；纯机制词条同时修改其消费脚本。

### 4.4 脚本对定制太古效果的消费

- `scripts/main/cardgame/card_script.ht`

- 不建立“所有机制字段自动乘 1.5”的通用逻辑。
- 没有合理定制的纯机制词条不配置 `greater`，自然退出随机太古池。

### 4.6 数据校验

涉及：`utils/data_validate/game_data_validate.dart`

新增校验：

- `greater` 只能为表，且至少含 `values` 或 `data` 之一。
- `values` 只能是 `multiply/add/set`，数值字段合法；有配置时下标不得超出 `valueData` 范围。
- 无 `valueData` 的词条不得配置 `greater.values`。
- `greaterAffixes` 的 rank 为 1～5、顺序合法，目标必须存在于本卡 `affixes` 且目标存在 `greater`。
- 普通随机词条的 `greater.data` 必须属于已登记、确有脚本消费方的契约字段，避免“看似能太古但实际无效果”。
- 绝世卡固定 `affixes` 不超过 3 条；无对应成长的纯机制词条给出错误或明确警告。
