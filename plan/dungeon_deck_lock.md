# 秘境入口锁定卡组计划

> 状态：待评审，尚未实施。

## 背景

局外保留多卡组，便于保存和尝试不同构筑；进入秘境后则锁定一个有效卡组，避免通过中途换卡组绕过敌人克制、垃圾牌、删改牌和临时卡牌等秘境规则。

当前战斗会按 `battleDeckIndex` 从局外卡牌库重新创建卡牌，因此只锁定编辑界面不足以让秘境修改跨战斗保留，需要独立的秘境卡组实例。

## 目标规则

- 进入秘境前必须从永久卡库选择一个有效卡组，数量固定为当前有效卡组下限，记录其来源并创建本次秘境卡组。
- 秘境期间不能切换、创建或删除卡组，也不能直接编辑局外卡组。
- 加入、删除、复制、升级、改费和修改词条等效果只作用于本次秘境卡组，并跨多场战斗保留。
- 当局结束时清除所有 `isDungeonCard == true` 的地牢专属卡牌、诅咒和临时数值修改。
- 缺省 `isDungeonCard: false` 的永久卡牌获得后即进入永久卡库，失败也保留；现有卡牌数据无需批量增加字段，当局使用深拷贝，回到营地后决定是否加入初始卡组。
- 明确标为永久升级的效果按原卡 ID 更新局外卡牌，不直接带回整张秘境副本。
- 秘境中途存档时保存入口卡组来源、当前秘境卡组状态与每张卡牌的 `isDungeonCard` 标记。

## 实现方向

秘境中维护独立状态，例如：

```text
dungeonDeck:
  sourceDeck
  cards
  originalCardId
  isDungeonCard
```

秘境内的战斗从 `dungeonDeck` 创建卡牌；普通战斗仍按现有 `battleDeckIndex` 创建。卡牌是否为地牢专属统一使用实例上的 `isDungeonCard`，缺省为 `false`，不复用符箓的 `isEphemeral`，也不与 `isUnpackable` 混用。

## 暂不包含

- 删除局外多卡组功能；
- 同伴轮战或战斗中补位；
- 具体秘境事件和卡牌奖励内容；
- 最终确定永久升级、临时诅咒及存档结构。
