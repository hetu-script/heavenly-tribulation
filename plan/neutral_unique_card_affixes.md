# 中立绝世卡牌固定词条与太古设计

> 状态：设计草案，供审阅；尚未修改卡牌数据、脚本、本地化或校验器。
>
> 范围：现有四张中立绝世卡——参玄功、先天功、分心诀、归元功。
> 目标：保留四张卡的主词条身份，为每张卡补齐三条固定额外词条与三条太古成长，并尽量复用现有中立词条和通用脚本。

## 1. 现状与设计原则

### 1.1 四张卡的现有主效果

| 卡牌   | 主词条 ID                    | 起始境界 | 当前主效果                                           |
| ------ | ---------------------------- | -------- | ---------------------------------------------------- |
| 归元功 | `heal_vigor_all`             | 0        | 0 费，消耗全部元气，每点回复生命上限 `{0}`% 的生命。 |
| 先天功 | `energy_positive_life`       | 1        | 0 费，获得 `{0}` 点元气。                            |
| 分心诀 | `opponent_reduce_resist_all` | 2        | 对手四种元素抗性 -`{0}`%。                           |
| 参玄功 | `draw_cards`                 | 3        | 抽 `{0}` 张牌。                                      |

### 1.2 固定成长规则

四张卡都应在主词条数据中显式写出：

- `affixes`：恰好三个额外词条 ID，顺序就是解锁顺序；主词条自身不包含在这个列表中。
- `greaterAffixes`：恰好三条，分别对应 rank 3、4、5；三个目标各不相同，且都属于 `affixes`。

实际解锁数量仍由现有生成规则决定：

| 卡牌实际境界 | 固定额外词条                         |
| ------------ | ------------------------------------ |
| rank 0       | 第 1 条                              |
| rank 1       | 第 1、2 条                           |
| rank 2 起    | 全部 3 条                            |
| rank 3、4、5 | 不再增加词条，依次应用指定的太古成长 |

因此，参玄功的 rank 0 特例是“原型仍配置三条，但初始只解锁第一条”；先天功、分心诀等高起始境界卡牌在最低生成境界就会解锁全部三条，并自动应用已经达到的太古境界。主词条永不参与太古。

### 1.3 内容原则

- 优先形成组合身份，而不是给四张卡分别堆三个高数值词条。
- 普通中立词条可以进入固定列表；需要读取特定主效果中间结果的词条标记为 `inUnpackable: true`，避免进入随机池后成为废词条。
- 新脚本应尽量通用化，数值、资源 ID、阈值和状态 ID 放在词条数据中。
- 太古只强化原有效果；反噬、门槛和触发次数不随意改变。
- 不为补负面而强行自伤。卡牌本身的资源消耗、自动转化、占牌库位置和部分效果只服务特定构筑，都可以构成方向性代价。

## 2. 方案总览

| 卡牌   | 三条固定额外词条（按解锁顺序）                                                  | 太古顺序（rank 3 → 4 → 5） | 设计方向                               |
| ------ | ------------------------------------------------------------------------------- | -------------------------- | -------------------------------------- |
| 归元功 | `qi_heal_armor` / `qi_heal_cleanse` / `qi_heal_shield`                          | 净化 → 护盾 → 护甲         | 按实际消耗的元气联动治疗、护甲和净化   |
| 先天功 | `vigor_threshold_shield` / `innate_conversion` / `innate_recoil`                | 护盾 → 太极转化 → 反噬护甲 | 元气爆发，但自动转化并抑制下回合资源   |
| 分心诀 | `opponent_vulnerable` / `opponent_weaken_attack_all` / `opponent_debuff_shield` | 破绽 → 易伤 → 全攻击削弱   | 复用中立减益，让非元素构筑也能利用此牌 |
| 参玄功 | `upgrade_hand_cards_neutral` / `profound_cost_reduction` / `draw_cards_neutral` | 减费 → 升级 → 额外抽牌     | 抽牌后参悟手牌，形成升级与当回合减费   |

## 3. 参玄功 `draw_cards`

### 3.1 设计意图

保留“直接抽牌”的简洁主效果，额外词条围绕“抽到之后如何参悟”展开：升级手牌、降低本次所抽卡牌的费用，最后增加抽牌数量。与悟道的天机术区分开：参玄功不观星、不抉择，也不承担流派规划功能。

### 3.2 固定词条与成长

| 解锁/太古境界 | 词条                                 | 来源                       | 效果                                                                  |
| ------------- | ------------------------------------ | -------------------------- | --------------------------------------------------------------------- |
| 3             | `upgrade_hand_cards_neutral` 参悟    | 新中立词条，可进入随机池   | 手牌中随机一张其他牌等级 +1，仅本场战斗生效。                         |
| 3             | `profound_cost_reduction` 豁然       | 参玄功专属，`inUnpackable` | 本次主词条抽到的牌，普通费用 -1，持续到本回合结束；动态费用不受影响。 |
| 3             | `draw_cards_neutral`                 | 现有中立词条               | 额外抽 1 张牌。                                                       |
| 3             | `upgrade_hand_cards_neutral`（太古） | 原效果强化                 | 升级为随机两张手牌各 +1 级，目标不重复。                              |
| 4             | `profound_cost_reduction`（太古）    | 原效果强化                 | 本次主词条抽到的牌普通费用 -2。                                       |
| 5             | `draw_cards_neutral`（太古）         | 原效果强化                 | 额外抽 2 张牌。                                                       |

所有抽牌仍受手牌上限约束；没有实际抽到的牌不能获得减费。参玄功自身在结算前已经离手，因此“随机手牌”不会选中自己。

### 3.3 结算顺序

主词条抽牌后，额外词条按以下顺序执行：

1. `upgrade_hand_cards_neutral`：可以升级本次刚抽到的牌。
2. `profound_cost_reduction`：只处理主词条本次实际抽到的牌。
3. `draw_cards_neutral`：最后追加抽牌；这批牌不再重复获得本次减费。

第三条额外词条会覆盖 `cardFlags.lastDrawnCards`，所以减费必须先于追加抽牌，实施时使用明确的 `priority`，不能依赖数据列表顺序。

### 3.4 实现复用

- `upgrade_hand_cards_neutral` 直接复用现有 `upgrade_hand_cards`，`filter: {}` 匹配全部手牌；普通值为 1 个目标，太古增加 1 个目标。
- `draw_cards_neutral` 已有数据和 `draw_cards` 脚本，无需改动。
- `profound_cost_reduction` 只需一个短脚本：遍历本次 `lastDrawnCards`，调用现有 `applyTurnCostModifier`；费用变化量为 `-value[0]`，动态费用继续由现有费用函数豁免。

### 3.5 备选方向

可以把追加抽牌换成“本次抽到的一张牌获得保留”，但保留会让参玄功与御剑养剑轴产生更多重叠，也会增强手牌长期囤积。当前优先推荐“升级＋减费＋追加抽牌”的轻量方案。

## 4. 先天功 `energy_positive_life`

### 4.1 设计意图

先天功是元气爆发入口，额外效果应让大量元气有即时用途，同时避免变成所有构筑都无脑使用的纯收益卡。

本方案形成固定顺序：

1. 主词条获得元气。
2. 元气充足时先获得护盾。
3. 自动把 4 点元气转化为太极之气，服务有色费用构筑。
4. 获得护甲和 1 层死气；死气通常会抵消下回合部分元气产出，形成“先天有余、后天受损”的节奏代价。

### 4.2 固定词条与成长

| 解锁/太古境界 | 词条                              | 来源                       | 效果                                                                    |
| ------------- | --------------------------------- | -------------------------- | ----------------------------------------------------------------------- |
| 2             | `vigor_threshold_shield` 元气护体 | 新中立词条，可进入随机池   | 主效果结算后，若当前元气不少于 5 点，获得 1 层护盾。                    |
| 2             | `innate_conversion` 先天化太极    | 先天功专属，`inUnpackable` | 上一步结算后，若当前元气不少于 4 点，消耗 4 点元气，获得 1 点太极之气。 |
| 2             | `innate_recoil` 先天反噬          | 先天功专属，`inUnpackable` | 获得 `{0}` 点护甲，随后获得 1 层死气。                                  |
| 3             | `vigor_threshold_shield`（太古）  | 原效果强化                 | 同样的 5 点门槛，获得 2 层护盾。                                        |
| 4             | `innate_conversion`（太古）       | 原效果强化                 | 仍消耗 4 点元气，改为获得 2 点太极之气。                                |
| 5             | `innate_recoil`（太古）           | 原效果强化                 | 护甲数值 ×1.5；死气仍为 1 层。                                          |

`innate_recoil` 的护甲建议以 `base: 3、increment: 0.15` 作为首轮数值起点，按现有卡牌数值公式求值；该数值需要在实装前与同境界普通防御卡比较，而不是直接沿用高数值通用防御词条。

### 4.3 关键口径

- 护盾判断发生在太极转化之前，所以可以先按转化前的元气获得护盾。
- 太极转化是自动效果，不要求玩家再次抉择。它使先天功更偏向有色费用构筑；只想用元气支付中立卡的构筑，需要接受这 4 点元气被自动转化。
- 死气是资源而非普通减益，不能被辟邪抵消。下回合元气产出会先与死气对冲；只有死气仍有剩余时，才按现有死气规则结算生命损失。
- 太极转化与死气均读取元气本色存量，不涉及其他有色气。

### 4.4 实现复用

- `vigor_threshold_shield` 可实现为通用的“资源达到阈值后获得状态”脚本，资源 ID、阈值、状态 ID 和数量均在词条数据中配置；太古只增加状态数量。
- `innate_conversion` 使用现有 `hasStatusEffect/removeStatusEffect/addStatusEffect` 即可完成，不需要修改支付系统。
- `innate_recoil` 可复用防御与自施状态的原子操作组合；太古只转换 `value[0]` 的护甲数值，不放大死气。
- 三个效果都在主词条之后执行，使用不同 `priority` 保证“护盾 → 转化 → 反噬”的顺序。

### 4.5 备选方向与复核点

如果自动消耗 4 点元气过于强制，可撤去 `innate_conversion`，改为“当前元气不少于 5 点时，获得 1 层无极之气”的通用输出词条。但该方案会明显增加永久伤害，且不再具有资源取舍，暂不作为首选。

## 5. 分心诀 `opponent_reduce_resist_all`

### 5.1 设计意图

主效果只降低元素抗性，对物理、真气、精神和纯粹构筑没有直接收益。推荐完全复用三个普通中立减益词条，使分心诀成为“通用进攻铺垫＋削弱敌方攻势”的绝世卡，同时验证普通中立词条通过固定组合也能形成绝世身份。

### 5.2 固定词条与成长

| 解锁/太古境界 | 词条                                 | 来源         | 效果                                          |
| ------------- | ------------------------------------ | ------------ | --------------------------------------------- |
| 2             | `opponent_vulnerable`                | 现有中立词条 | 对手获得 `{0}` 层易伤，任何类型伤害均可利用。 |
| 2             | `opponent_weaken_attack_all`         | 现有中立词条 | 对手徒手、武器、法术、咒术攻击力 -`{0}`%。    |
| 2             | `opponent_debuff_shield`             | 现有中立词条 | 对手获得 1 层破绽，下一次受到的伤害翻倍。     |
| 3             | `opponent_debuff_shield`（太古）     | 现有太古配置 | 破绽由 1 层提高至 2 层。                      |
| 4             | `opponent_vulnerable`（太古）        | 现有太古配置 | 易伤数值 ×1.5。                               |
| 5             | `opponent_weaken_attack_all`（太古） | 现有太古配置 | 全攻击削弱数值 ×1.5。                         |

分心诀起始境界为 rank 4，因此最低生成时已经解锁全部三条，并且破绽、易伤已经太古化；rank 5 再获得全攻击削弱的太古版本。

### 5.3 构筑定位

- 元素队同时使用主词条的元素抗性和三条通用减益。
- 非元素队可以把主词条视为未命中构筑的部分，利用易伤、破绽进行爆发，并以全攻击削弱获得防御价值。
- 辟邪可以按现有规则抵消这些负面状态；多层破绽需要分别抵消，不提供不可反制的额外保证。

### 5.4 数值复核点与备选

这套方案不需要新脚本，但高境界通用词条也会按公式成长。rank 4 直接获得“太古易伤＋太古破绽＋全抗下降＋全攻击削弱”，需要重点复核单回合爆发是否过高。

如果实测过强，优先把 `opponent_weaken_attack_all` 换成 `opponent_debuff_speed_slow`，转为行动控制，而不是继续叠加伤害；若需要单独调低数值，再设计分心诀专属词条，不为了调数值而提前复制三个同效果 ID。

## 6. 归元功 `heal_vigor_all`

### 6.1 设计意图

主效果消耗全部元气，天然具有资源代价。额外词条应解决两个问题：

- 高境界治疗量可能溢出，需要同时提供护甲收益。
- 0 费打出不能在没有元气时白赚护盾、净化等固定效果，因此额外收益应读取“本次实际消耗的元气”。

### 6.2 主效果增加中间结果

参照蓄灵诀的 `lastManaGained`，主脚本 `heal_vigor_all` 在消耗前记录：

- `cardFlags['lastVigorConsumed']`：本次实际消耗的元气数量；没有元气时也明确写 0。
- 随后仍按现有逻辑消耗元气并治疗，主效果的数值和顺序不变。
- 每次出牌都会重置 `cardFlags`，后续词条只读取本牌本次结果，不能读取上一张卡的残留。

### 6.3 固定词条与成长

| 解锁/太古境界 | 词条                      | 来源                       | 效果                                                         |
| ------------- | ------------------------- | -------------------------- | ------------------------------------------------------------ |
| 0             | `qi_heal_armor` 气疗化甲  | 归元功专属，`inUnpackable` | 若本次消耗至少 3 点元气，获得 `{0}` 点护甲。                 |
| 1             | `qi_heal_cleanse` 涤荡    | 归元功专属，`inUnpackable` | 若本次消耗至少 3 点元气，额外移除 1 层可驱散的普通负面状态。 |
| 2             | `qi_heal_shield` 气疗护体 | 归元功专属，`inUnpackable` | 若本次消耗至少 3 点元气，获得 1 层护盾。                     |
| 3             | `qi_heal_armor`（太古）   | 原效果强化                 | 每点消耗元气提供的护甲 ×1.5。                                |
| 4             | `qi_heal_cleanse`（太古） | 原效果强化                 | 额外移除 2 层可驱散的普通负面状态。                          |
| 5             | `qi_heal_shield`（太古）  | 原效果强化                 | 获得 2 层护盾，消耗门槛不变。                                |

`qi_heal_armor` 建议以 `base: 3、increment: 0.15` 作为首轮数值起点。它按消耗量而不是实际治疗量结算，因此即使生命已满或治疗溢出，仍能保留防御价值。

### 6.4 净化口径

- 主效果现有治疗仍会在实际回复生命时随机移除 1 层负面状态；`qi_heal_cleanse` 是额外的 1/2 层，不取代主效果。
- 额外净化从 `Constants.debuffs` 对应的可驱散普通负面状态中移除，不影响永久状态、资源阴气或其他非减益状态。
- 没有实际消耗元气时，额外净化和护盾均不触发，护甲也自然为 0。
- 即使生命已满、主效果没有产生实际治疗，额外净化仍可生效，让归元功保留“耗气涤体”的用途。

### 6.5 备选方向

“把溢出治疗转化为护甲”也很契合此卡，但需要主脚本同时返回实际治疗量和溢出量，并统一满血、超过当前生命上限等口径。首版推荐直接按消耗元气提供护甲，机制更简单，也避免高境界无限放大溢出治疗。

## 7. 词条入池与脚本范围

### 7.1 可进入普通中立随机池

- `upgrade_hand_cards_neutral`：rank 1，攻击/加持；复用 `upgrade_hand_cards`。
- `vigor_threshold_shield`：rank 2，加持；复用新的通用“资源门槛授予状态”脚本。
- `draw_cards_neutral`、`opponent_vulnerable`、`opponent_weaken_attack_all`、`opponent_debuff_shield`：均已存在，继续沿用现有池和太古配置。

### 7.2 仅作为绝世固定词条

以下词条写 `inUnpackable: true`，不进入普通随机池：

- `profound_cost_reduction`：依赖本牌主效果刚刚产生的抽牌记录。
- `innate_conversion`、`innate_recoil`：组成先天功的定向转化与反噬，不适合随机附加到其他卡。
- `qi_heal_armor`、`qi_heal_cleanse`、`qi_heal_shield`：依赖 `lastVigorConsumed`，其他卡无法保证提供该中间结果。

### 7.3 预计实现范围

首选方案不需要新增 Dart 战斗机制，主要改动为：

- `assets/data/cards.json5`：四张主词条补充 `affixes` 与 `greaterAffixes`。
- `assets/data/card_affixes.json5`：新增中立/专属词条及太古配置。
- `scripts/main/cardgame/card_script.ht`：增加抽牌减费、资源门槛、太极转化、反噬和气疗联动脚本；`heal_vigor_all` 记录本次消耗量。
- `assets/locale/zh/rpg/battlecard.json`：新增词条描述与必要的关键词。
- `utils/data_validate/game_data_validate.dart`：按第 8 节收紧绝世卡牌固定成长校验。
- 相关玩法文档、MOD 契约和 `.agents/context/battle_system.md`：仅在实际实施后同步已实现规则。

## 8. 数据校验的强制要求

当前 `checkGreaterAffixGrowth` 已经在 `affixes` 存在时检查三条 `greaterAffixes`、目标引用、解锁境界和 `greater`，但仍允许绝世卡缺少 `affixes`、不足三条额外词条，或在没有额外词条时完全跳过成长检查。

实施本设计时，应将绝世卡牌规则收紧为无条件校验：

1. 每个 `isUnique: true` 的卡牌主词条必须显式提供 `affixes`，且为长度恰好 3 的列表。
2. 三个词条 ID 必须存在于 `card_affixes.json5`；不得重复，并继续通过既有词条结构、脚本和本地化校验。
3. 必须显式提供 `greaterAffixes`，且为长度恰好 3 的列表。
4. 三项分别使用 rank 3、4、5，顺序固定；`affixId` 必须属于本卡的 `affixes`，且三个目标不得重复。
5. 每个太古目标在对应 rank 必须已经解锁，并具有合法 `greater`；主词条不能成为目标。
6. 规则适用于全部绝世卡，包括 rank 0 的参玄功、天赋授予卡和化神洗入卡，不设置中立卡例外。

这四张旧卡在当前状态下会触发新校验错误，因此校验器收紧必须与四张卡的数据补齐放在同一次实施中，避免把“已知的旧数据缺漏”长期留在校验失败状态。

测试时应覆盖：

- 全部绝世卡在 rank 5 均为 1 主＋3 额外，且三个额外词条全部太古。
- 参玄功从 rank 0 逐境成长时依次解锁 1/2/3 条，rank 3～5 依次太古。
- 先天功、分心诀等高起始境界卡直接生成时，自动获得已达成的词条和太古，结果与逐境成长一致。
- 缺少 `affixes`、不足或超过三条、缺少 `greaterAffixes`、目标重复、目标未解锁、目标无 `greater` 均被校验器拒绝。

## 9. 审阅时建议优先确认

1. 先天功是否接受“自动消耗 4 点元气转太极”的方向性限制；若不接受，应采用第 4.5 节备选，而不是在实施时静默改成可选效果。
