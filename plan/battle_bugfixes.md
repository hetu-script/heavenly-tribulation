# 战斗与随机词缀问题修复计划

> 状态：已于 2026-09-18 实施并重新编译 Hetu 模组。

## 一、已确认的现行规则

以下行为以当前代码为准，不在本次修复中调整：

- 劫气沿用当前代价与结算规则。
- 剑气相关的出牌统计以 `cardType == "weapon"` 为准，所有武器牌都计入，不额外要求 `category == "attack"`。
- 原问题第 7 点的本地化缺失已经修复，本计划不再修改对应本地化文件。
- 敌我对称性只修复敌方易逝牌的去向，不延伸到敌方卡组合法性检查、符箓次数结算或其他流程重构。

## 二、修复范围总览

| 序号 | 问题 | 主要位置 | 目标行为 |
| --- | --- | --- | --- |
| 1 | 手牌伤害预测读取非伤害词条时可能报错 | `lib/scene/battle/character.dart`、`lib/scene/battle/battle.dart` | 只预测结构完整的伤害词条，其余词条返回无预测值 |
| 2 | `removeStatusEffect(id)` 无参数时实际移除 0 层 | `lib/scene/battle/character.dart`、`scripts/main/cardgame/status_script.ht` | 无数量参数时移除该状态的全部层数 |
| 3 | 元素异常充能在本次伤害结算前生效 | `lib/scene/battle/character.dart` | 已满阈值后的下一次元素伤害触发异常，与暴击充能时序一致 |
| 4 | 卡牌等级与主词缀等级可能不一致 | `scripts/main/cardgame/card.ht` | 主词缀始终使用 `card.level`，升级不再随机重随或降级 |
| 5 | 后手恢复规则与代码、注释不一致 | `lib/scene/battle/battle.dart` | 非偷袭战斗中，后手方恢复到当前战斗生命上限 |
| 6 | 敌方易逝牌打出后进入弃牌堆 | `lib/scene/battle/battle.dart` | 敌方易逝牌与玩家易逝牌一样碎裂并离场 |
| 7 | 装备主词条未参与词条唯一性判定 | `scripts/main/data/item/equipment.ht` | 生成额外词条前，先登记主词条的唯一 ID |

## 三、详细实施方案

### 1. 伤害预测的结构检查

#### 原因

`refreshHandCardDescriptions()` 会把一张牌的每个词条都传给 `predictDamage()`。当前 `predictDamage()` 在判断词条是否代表伤害之前，就把 `value` 强制当作列表、把 `damageType` 强制当作字符串读取。治疗、防御、状态和部分无数值词条并不具备这些字段，因此混合词缀卡牌刷新描述时可能出现运行时类型错误。

#### 修改方案

- 在 `BattleCharacter.predictDamage()` 的入口先验证词条是否为可预测的直接伤害词条：
  - `category == "attack"`；
  - `value` 是非空列表，且首项是数值；
  - `damageType` 是非空字符串。
- 任一条件不满足时直接返回 `null`，不进入伤害、暴击和异常计算。
- `refreshHandCardDescriptions()` 继续为每个词条写入预测字段；返回 `null` 时写入空值，以清除可能遗留的旧预测，不改变原始 `value`。
- 不尝试预测由脚本回调、状态效果或额外词条间接造成的伤害；本次只消除错误并保持当前“确定性直接伤害预测”的边界。

#### 验收标准

- 纯攻击牌仍显示预测伤害、暴击和异常层数。
- 同时带攻击、治疗、防御或状态额外词条的牌能正常刷新描述，不抛出类型错误。
- 纯增益牌、无 `valueData` 词条和无 `damageType` 词条不显示伪造的伤害预测。

### 2. 状态无参数移除语义

#### 原因

`removeStatusEffect()` 只有传入 `amount`、`percentage` 或 `force: true` 时才计算 `removedAmount`。脚本中多处使用 `removeStatusEffect(id)` 表达“耗尽/移除该状态”，目前却会减去 0 层。

已确认受影响的无参数调用包括：

- `dodge_invincible`：持续期结束后移除全部无敌。
- `dodge_staggering`：持续期结束后移除全部踉跄。
- `vulnerable`：触发伤害加深后消耗全部易伤。
- 雷元素异常：结算后耗尽全部层数。
- 冰元素异常：结算后耗尽全部层数。

#### 修改方案

- 将 API 默认语义确定为：未提供 `amount` 和 `percentage` 时，移除当前状态的全部层数。
- 保留现有显式语义：
  - `amount` 移除指定层数；
  - `percentage` 按比例向上取整；
  - 资源不足时的“全有或全无”规则保持不变；
  - `force` 仍用于绕过资源状态的存量限制，不再是“全部移除”唯一入口。
- 更新方法注释，使 Dart 与 Hetu 调用方都能明确默认行为。
- 全局审计所有无参数调用；符合“全部移除”意图的调用保留简写，不符合该意图的调用改为显式 `amount` 或 `percentage`。

#### 验收标准

- 无参数调用返回实际移除的全部层数，并删除对应状态组件。
- 上述五类状态均按脚本注释正确消耗。
- 显式按层、按比例以及资源支付逻辑不发生回归。
- 状态移除后的图标排列和资源气显示仍正常刷新。

### 3. 元素异常充能时序

#### 原因

物理暴击在检查 `crit_charge` 后才为本次伤害增加充能，因此达到阈值的这一击不会立即暴击；元素伤害目前先增加 `ailment_charge`，再检查阈值，导致达到阈值的这一击立即造成异常。两套同类机制的时序不一致，也与代码注释矛盾。

#### 修改方案

- 元素伤害的结算顺序改为：
  1. 使用本次伤害开始前已有的 `ailment_charge` 判断是否触发异常；
  2. 达到阈值时消耗阈值层数并根据本次最终伤害生成异常；
  3. 完成本次异常结算后，再为这次实际元素伤害增加 1 层 `ailment_charge`。
- “幸运保证异常”继续走独立路径：不消耗异常充能，但本次实际元素伤害仍正常获得 1 层充能。
- 物理暴击现有“先检查、后充能”行为不变，只同步整理注释和代码位置，避免之后再次出现时序漂移。
- `predictDamage()` 继续仅依据当前已有充能进行预测，从而与实际结算一致。

#### 验收标准

- 阈值为 N、战前有 N-1 层时：本次元素伤害不触发异常，结算后变为 N 层。
- 战前已有 N 层时：本次元素伤害触发异常、消耗 N 层，结算后因本次伤害留下 1 层。
- 幸运保证异常时无需满充能即可触发，且不会错误消耗已有异常充能。
- 暴击充能行为无变化。

### 4. 卡牌等级与主词缀等级一致性

#### 原因

卡牌构造时先生成 `card.level`，随后 `_updateAffixValue()` 又根据词缀境界随机生成 `affix.level`，因此主词缀等级可能与卡牌等级不同。`upgradeCard()` 先把卡牌等级加 1，再调用同一个随机函数，可能把主词缀重随到任意等级，甚至表现为降级。

#### 修改方案

- 明确不变量：`card.affixes.first.level == card.level`。
- 将“按给定等级重算数值”和“随机词缀等级”拆开：
  - 数值重算函数不再隐式调用随机数，只使用词缀已经确定的等级或显式传入的等级；
  - 只有确实需要重随额外词缀的流程调用 `_randomizeAffixLevel()`。
- 卡牌构造时先确定合法的 `card.level`，再把同一等级赋给主词缀并计算其 `value`。
- `rerollAffix()` 若按现有打造规则重随卡牌等级，则在新 `card.level` 确定后按该等级重算主词缀；额外词缀仍按原规则独立重随。
- `upgradeRank()` 中：
  - 先确定不会低于旧等级的新 `card.level`；
  - 主词缀按 `card.level` 重算；
  - 需要免费重随的额外词缀显式走随机函数，以保留现有破境行为。
- `upgradeCard()` 每次只把卡牌等级提高 1（不超过当前境界允许的等级上限），随后按新等级确定性重算主词缀，不重随其他词缀。
- 对无数值主词缀也同步保存主词缀等级，保证对象数据的一致性。

#### 验收标准

- 新生成、重随、破境及临时升级后的卡牌，`card.level` 均与主词缀等级相同。
- `upgradeCard()` 不会改变主词缀身份、随机降低等级或重随额外词缀。
- 卡牌达到当前境界等级上限后不会越界。
- 破境和额外词缀打造原本需要的随机性仍保留，费用仍按卡牌境界正确重算。

### 5. 后手方全部恢复

#### 原因

文件顶部仍声明“恢复 20%”常量，但实际结算没有使用该常量；现有 `overheal` 公式混用了基础生命上限和战斗生命上限，提示的恢复量也可能不等于实际变化。

#### 修改方案

- 删除未使用的 `kSecondHandHealRate` 及“20%/少量恢复”注释。
- 非偷袭战斗确定先后手后，计算后手方相对当前 `lifeMax` 的缺失生命：`lifeMax - life`。
- 缺失生命大于 0 时，将生命恢复到当前战斗生命上限，并显示准确的实际恢复量。
- 已满血或处于超额生命时不处理，不借此压低现有生命。
- 偷袭战斗继续不给予后手恢复。

#### 验收标准

- 普通战斗中，后手方从任意低于上限的生命恢复到当前战斗生命上限。
- 恢复提示数值等于恢复前后的实际差值。
- 满血、超额生命和偷袭三种情况均不产生错误治疗或误导提示。

### 6. 敌方易逝牌打出后碎裂

#### 原因

玩家出牌流程会判断 `isEphemeral`：易逝牌播放碎裂效果并移出场景；敌方出牌流程则无条件把牌放入弃牌堆，导致同一牌属性在敌我双方具有不同含义。

#### 修改方案

- 将“已打出卡牌的去向”整理为敌我共用的结算逻辑，或在敌方流程中复用与玩家完全相同的判断：
  - 易逝牌：播放 `CardShatterEffect`，从手牌/场景移除，不加入弃牌堆；
  - 普通牌：翻面后加入对应弃牌堆并排序。
- 玩家已有的 `usedInBattle` 标记及战后符箓次数结算保持现状。
- 敌方易逝牌不会进入玩家 `heroDeck` 的次数结算范围，不新增敌方符箓持久次数系统。

#### 验收标准

- 敌方打出易逝牌后，该牌不在手牌、抽牌堆或弃牌堆中，并播放碎裂效果。
- 敌方普通牌仍正常进入敌方弃牌堆。
- 玩家易逝牌的碎裂和战后次数扣除行为不变，敌方出牌不会扣除玩家符箓次数。

### 7. 装备主词条加入唯一 ID 集合

#### 原因

装备生成时先创建 `affixUniqueIds`，但把主词条唯一 ID 加入集合的代码被注释。随后筛选额外词条只检查该集合，因此同时具备 `isEquipmentMain` 与 `isEquipmentExtraAffix` 的词条可能在同一件装备上重复出现。

#### 修改方案

- 主词条加入 `this.affixes` 后、生成任何额外词条前，立即登记主词条的唯一性标识。
- 与卡牌词条的兼容规则对齐：
  - 若主词条声明 `uniqueIds` 列表，则全部加入；
  - 否则加入 `uniqueId`；
  - 两者都没有时以主词条 `id` 作为回退值。
- 保留额外词条生成后登记 `affix.uniqueId ?? affix.id` 的现有行为。
- 载入已有装备数据时继续重建唯一 ID 集合，确保后续打造/扩展流程不会绕过去重规则；不在本次计划中批量重写存档。

#### 验收标准

- 同一件新生成装备的额外词条不会与主词条使用相同 `id`/`uniqueId` 组。
- 额外词条之间的现有互斥规则不回归。
- 只有 `id`、只有 `uniqueId`、以及声明 `uniqueIds` 列表的主词条都能正确登记。

## 四、实施顺序

1. 修复卡牌等级计算与装备词条唯一性，先稳定随机数据对象的不变量。
2. 修复 `removeStatusEffect()` 默认语义，并逐一审计 Hetu 无参数调用。
3. 修复伤害预测入口检查和元素异常充能时序，使显示与实际结算保持一致。
4. 修复后手全部恢复和敌方易逝牌去向。
5. 重新编译 Hetu 脚本，执行静态检查与针对性战斗回归。

### 手工回归矩阵

| 场景 | 重点观察 |

## 六、明确非目标

- 不调整劫气代价、产出或其他资源平衡。
- 不改变剑气对所有武器牌的统计规则。
- 不修改用户已经修复的第 7 点本地化。
- 不重做伤害预测器以模拟所有脚本和随机效果。
- 不扩展敌方卡组合法性、符箓持久次数或存档迁移系统。
- 不处理本轮审查之外的天赋树、丹药及装备机制设计。
