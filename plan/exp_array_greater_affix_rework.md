# 聚灵阵轮数与临时太古词条改造计划

> 本文只规划聚灵阵与临时增益改造，不执行卡牌、装备或普通丹药的词条数量调整。
>
> 与 `plan/greater_affix_rework.md` 共用 `greater` 数据契约，但聚灵阵使用独立的临时奖励流程。

## 1. 背景与目标

聚灵阵目前通过“聚光 + 选文”的多轮冥想，让玩家按攻击、防御、属性、资源类别获得临时被动。发展度影响灵石成本、轮数、词条境界和等级。

当前存在三个问题：

- 轮数最初与最高境界 6 个额外词条对齐，最高可达 6 轮；词条上限调整为 3 后，继续保留 6 轮会增加重复操作。
- 同一轮冥想可以重复获得同 ID 词条，`characterSetEphemeralPassive` 直接覆盖同名被动，可能浪费一轮，甚至以较低数值覆盖较高数值。
- 每轮奖励基本等价，完整冥想缺少收尾高潮，高发展度主要体现为更多轮数，而不是更高品质。

本次改造目标：

- 聚灵阵每次冥想最多 3 轮、最多获得 3 条本次新增临时词条。
- 避免同一次冥想中的重复词条和无效轮次。
- 结丹后开放一次“凝炼”，由玩家从本次获得的合格词条中主动选择一条升级为临时太古。
- 普通丹药和普通装备不产生太古；聚灵阵成为临时太古增益的专属来源。
- 临时太古不自动锁定，仍与普通临时被动一样在战斗结束后清除。

## 2. 最终规则

### 2.1 冥想轮数

| 聚灵阵发展度   | 普通冥想轮数 | 凝炼                                      |
| -------------- | -----------: | ----------------------------------------- |
| 无（rank 0）   |            1 | 无                                        |
| 凝气（rank 1） |            2 | 无                                        |
| 筑基（rank 2） |            3 | 无                                        |
| 结丹（rank 3） |            3 | 完成普通轮次后，可选择 1 条合格词条太古化 |
| 还婴（rank 4） |            3 | 同结丹，词条境界、等级与候选池继续提升    |
| 化神（rank 5） |            3 | 同结丹，词条境界、等级与候选池继续提升    |

轮数公式改为 `min(development + 1, 3)`。

首期每次完整冥想最多凝炼 1 条，避免六类临时增益与多条太古在一次战斗前叠加过强。还婴、化神暂不通过增加轮数或凝炼条数成长，而通过词条境界、等级和候选池成长。

灵石成本、每次交互的时间消耗保持现规则，不因轮数上限调整而额外修改。

### 2.2 普通轮次与重复处理

- `_expArrayGrantedBuffs` 不再只记录类别，改为记录本次实际获得的词条 ID。
- `getExpArrayBuff` 接收本次已获得 ID 列表，候选池先排除这些 ID。
- 若某类别在本次冥想中已无新词条可给：
  - 不推进轮数；
  - 不消耗该次选文对应的游戏时间；
  - 给出提示，让玩家改选其他类别。
- 本次冥想最多获得 3 条不同 ID 的临时词条。
- 跨冥想仍允许同 ID 词条出现，但普通版本不得覆盖已有的太古版本；新的普通同 ID 词条到来时保留太古并提示。新的太古版本可由玩家主动凝炼替换。

### 2.3 结丹后的凝炼流程

普通轮次全部完成后，若发展度不低于 3：

1. 收集本次获得、带有合法 `greater` 配置且尚未太古的词条。
2. 进入独立“凝炼”阶段，展示这些词条的当前描述和太古后的预览。
3. 玩家选择 1 条进行太古化，或选择放弃并结束。
4. 没有合格候选时跳过凝炼，直接完成冥想，不强迫玩家进行无意义选择。
5. 凝炼完成后刷新被动说明，再进入原有完成提示和退出流程。

凝炼使用确定选择，不再叠加 5% 等额外随机概率。当前系统已经有词条 ID 和等级两层随机，由玩家主动选择太古目标能更好地体现操作与构筑价值。

### 2.4 临时太古规则

- 只处理 `isEphemeral: true` 的临时被动，不处理永久属性、天赋或普通丹药主词条。
- 复用 `plan/greater_affix_rework.md` 的 `greater` 配置：
  - `greater.values` 控制指定数值的 `multiply/add/set`；
  - `greater.data` 只由明确实现消费逻辑的脚本读取；
  - 没有 `greater` 配置的词条不能凝炼。
- 凝炼时将词条等级设为聚灵阵当前发展度对应境界的满级，再按被动数值公式和太古规则重算。
- 不写入 `isFreezed`，不引入打造锁定概念。
- `isGreater` 只表示品质与展示，不改变 `isPermanent`；战斗结束仍按现有 `clearEphemeralPassives` 规则清除。
- 普通丹药、装备生成和卡牌生成不因本计划获得太古。

## 3. 代码修改范围

### 3.1 聚灵阵场景流程

主要文件：`lib/scene/cultivation/cultivation.dart`

步骤：

1. 将 `_expArrayMaxRounds` 的计算改为最高 3 轮。
2. 将 `_expArrayGrantedBuffs` 改为本次已获得词条 ID 集合。
3. `_onExpArrayPhraseTap` 接收 `getExpArrayBuff` 的返回结果：
   - 成功时记录词条 ID、推进轮数并消耗时间；
   - 类别耗尽时只提示，不推进轮数、不消耗时间。
4. 普通轮次完成后，在发展度不低于 3 时进入凝炼阶段；否则走原完成流程。
5. 新增凝炼阶段（可复用 `_meditatePhrases` 和选文布局）：
   - 显示候选词条及太古预览；
   - 玩家选择词条或放弃；
   - 选择后调用脚本升级并刷新描述。
6. 冥想重开、失败和完成时统一清理本次 ID 集合与凝炼候选状态。

### 3.2 临时词条生成与凝炼

涉及：

- `scripts/main/binding/player.ht`
- `scripts/main/data/character/battle_entity.ht`

步骤：

1. `getExpArrayBuff(type, rank, {excludeIds})` 增加排除列表，过滤本次已获得 ID；成功时返回词条 ID，类别耗尽时返回空结果。
2. 修正该函数注释中的类别说明，与实际的 `attack/defense/attribute/energy` 一致。
3. 新增专用的临时被动凝炼函数，例如 `upgradeExpArrayBuffToGreater(character, dataId, rank)`：
   - 只处理 `character.ephemeralPassives` 中已有词条；
   - 检查原词条存在 `greater` 配置；
   - 设置 `isGreater`、当前境界满级和最终数值；
   - 不设置 `isFreezed` 或 `isPermanent`。
4. 临时被动实例需要保留 `greater` 配置，供已实现的定制效果读取；普通被动的其他计算路径不被迫接受太古。
5. 普通同 ID 被动覆盖前检查已有 `isGreater`，避免普通丹药或下一次普通冥想意外抹掉太古。

### 3.3 数值与定制效果

涉及：

- `assets/data/passives.json5`
- 必要时 `scripts/main/cardgame/status_script.ht` 或其他对应消费脚本
- `lib/logic/logic.dart`（仅当共享太古数值 helper 尚未实现时）

步骤：

1. 为 `isEphemeral` 词条逐条配置或禁止 `greater`，优先处理伤害、护甲、属性和固定次数等明确数值。
2. 被动普通值继续由 `calculatePassiveAffixValue` 计算，再应用 `greater.values`，不修改普通公式。
3. 纯机制词条只有存在明确 `greater.data` 消费方才允许凝炼；否则从候选中排除。
4. 不统一缩放阈值、费用、资源、百分比或全部机制字段。

### 3.4 展示与本地化

涉及：

- `lib/data/game.dart`
- `assets/locale/zh/site.json`
- 相关玩法文档

步骤：

1. `_getPassivesDescription` 在临时太古词条前复用 `kAffixLeading2 = '✶'`，并将整行设为黄色；普通临时被动保持原样式。
2. 凝炼候选同时显示当前描述与太古预览，明确本次只能选一条。
3. 增加凝炼提示、放弃、成功、无候选、类别耗尽和普通词条无法覆盖太古等本地化文本。
4. 不新增 Unicode 字符常量。

### 3.5 数据校验与文档

涉及：

- `utils/data_validate/game_data_validate.dart`
- `docs/docs/how2play/rpg/item/consumable/readme.md`
- `docs/docs/how2play/rpg/cultivation/readme.md`
- `plan/battle_system_overview.md`

步骤：

1. 与卡牌太古共用 `greater` 结构校验，确保 `isEphemeral` 词条的 `greater.data` 有真实消费方。
2. 丹药文档明确：普通丹药不直接产生太古，临时太古仅来自聚灵阵凝炼。
3. 修炼文档补充轮数表、重复处理、凝炼解锁与战斗后清除规则。
4. 总览更新聚灵阵的临时被动来源与临时太古展示/清除路径。

## 4. 推荐实施顺序

### 阶段一：普通冥想整理

1. 轮数封顶为 3。
2. `getExpArrayBuff` 返回 ID 并支持本次排除。
3. 完成类别耗尽不耗时、同次不重复和普通不覆盖太古的保护。

### 阶段二：临时太古

1. 复用或实现被动太古数值 helper。
2. 为临时词条配置 `greater`。
3. 实现单条凝炼函数、结丹后的候选选择和放弃流程。
4. 完成 `✶` 黄色展示及本地化。

### 阶段三：验证与文档

1. 完成数据校验、单元测试和脚本编译。
2. 验证战斗结束清除和普通丹药行为不变。
3. 同步玩法文档与系统总览。

## 5. 测试计划

项目已有测试，可新增 `test/exp_array_test.dart`，并复用现有 Hetu 测试方式。

### 轮数与生成

- development 0～5 的轮数分别为 1、2、3、3、3、3。
- 同一次冥想不会获得重复 ID。
- 类别耗尽时不推进轮数、不消耗时间，可选择其他类别。
- 灵石成本、词条 rank 和等级区间保持原规则。

### 凝炼

- development 0～2 不开放凝炼，development 3～5 在普通轮次后开放。
- 每次完整冥想最多凝炼 1 条，可以放弃。
- 无 `greater` 配置或无消费方的词条不会进入候选。
- 凝炼后等级为当前境界满级，数值只按配置变化一次。
- 普通同 ID 被动不能覆盖已有太古。

### 展示与生命周期

- 临时太古在被动说明中显示 `✶` 和黄色文本。
- 战斗开始时太古正常参与属性聚合。
- 战斗结束后临时太古与其他非永久临时被动一起清除。
- 普通丹药、装备和卡牌生成路径未因本计划产生太古。

## 6. 验证命令与人工验收

执行：

```bash
dart run utils/data_validate/game_data_validate.dart
flutter analyze
flutter test
python build.py
```

人工验收：

1. 分别使用 development 0～5 的聚灵阵完成冥想，确认轮数和候选池。
2. 在同一冥想中重复选择同类别，确认不会浪费轮次或重复覆盖。
3. 在结丹以上聚灵阵完成 3 轮，选择、预览并确认 1 条临时太古。
4. 再进行一次普通冥想或使用普通同 ID 丹药，确认普通版本不会覆盖太古。
5. 完成一场战斗，确认临时太古正常生效并在战后清除。
6. 确认普通丹药生成和使用行为未改变。

## 7. 完成标准

- 聚灵阵每次冥想最多 3 轮、3 条不同 ID 的新临时词条。
- 类别耗尽不耗时、不推进轮数，普通版本不能覆盖已有太古。
- 结丹后每次完整冥想可由玩家主动凝炼最多 1 条临时太古。
- 临时太古只来自聚灵阵，展示统一为 `✶` 黄色，战斗后正常清除。
- 普通丹药、装备、卡牌的生成规则未被本计划修改。
- 数据校验、静态分析、脚本编译及完整测试通过，相关文档与本地化已同步。
