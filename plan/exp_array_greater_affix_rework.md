# 聚灵阵与丹药临时增益改造计划

> 本文统一规划丹药和聚灵阵产生的临时增益如何生成待生效配置、替换、生效与清除，不修改卡牌、装备或丹药的词条数量及生成太古规则。
>
> `greater` 数据契约、数值 helper、主词条固有强化、普通丹药生成太古和永久被动聚合，均以 `plan/greater_affix_rework.md` 为准。本文复用这些能力，不再定义同 ID 普通/太古覆盖规则。

## 1. 背景与目标

聚灵阵目前通过“聚光 + 选文”的多轮冥想，让玩家按攻击、防御、属性、资源类别获得临时被动。发展度影响灵石成本、轮数、词条境界和等级。丹药与聚灵阵目前可以反复使用并叠加不同批次的临时效果，同 ID 效果又会直接覆盖，导致以下问题：

- 不同批次的丹药和聚灵阵效果可以持续叠加，战前准备逐渐变成重复消耗与堆叠，规则不直观。
- 聚灵阵轮数最初与最高境界 6 个额外词条对齐，最高可达 6 轮；词条上限调整为 3 后继续保留 6 轮会增加重复操作。
- 同一次冥想可以重复获得同 ID 词条，可能浪费一轮。
- 每轮奖励基本等价，完整冥想缺少收尾高潮。
- 如果只为处理叠加而继续增加普通/太古覆盖规则，会让丹药、聚灵阵和不同品质之间的交互越来越复杂。

本次改造目标：

- 将每批丹药或聚灵阵增益视为一套独立的临时配置；成功完成新准备后，以新配置整体替换旧的非永久临时配置。
- 只有主词条、没有额外词条的丹药保留现有配置，提供安全使用主效果的途径。
- 聚灵阵先构建本次待生效配置，成功完成后一次性替换；失败或取消不影响旧配置。
- 聚灵阵每次冥想最多 3 轮、最多获得 3 条不同 ID 的新临时词条。
- 结丹后开放一次定向“凝炼”，由玩家从本次获得的合格词条中选择一条升级为临时太古。
- 普通丹药和普通装备沿用主计划的生成太古规则；聚灵阵的独特性是定向选择临时太古，而非独占临时太古来源。

### 非目标

- 不修改普通丹药、装备和卡牌的词条数量与生成太亘古径。
- 不修改永久被动、天赋或已经转为永久的效果。
- 不要求本期实现移除丹药额外词条的打造；后续可用坐忘类打造把丹药加工为仅主词条的安全版本。

## 2. 最终规则

### 2.1 临时配置与整体替换

临时增益区分两种状态：

- **当前生效配置**：已经写入角色 `ephemeralPassives` 并参与属性计算的本批次效果。
- **待生效配置**：聚灵阵冥想过程中独立构建、尚未写入角色正式被动的新批次效果。

整体替换遵守以下规则：

1. 含额外词条的丹药成功服用，或聚灵阵成功完成后，清除当前所有 `isPermanent != true` 的临时被动，再应用新配置。
2. 永久被动、天赋以及已经转为永久的效果不清除。不能简单删除整个 `ephemeralPassives` 而不检查 `isPermanent`。
3. 除 2.2 节仅主词条丹药的明确例外，不同批次不再叠加，也不再需要“普通不能覆盖太古”“太古替换太古”等同 ID 保护规则。普通新配置同样可以替换包含太古的旧配置。
4. 替换失败、物品不可使用或聚灵阵中途失败/取消时，不清除旧配置。
5. 所有产生临时被动的入口都必须遵守同一批次规则，包括普通丹药、聚灵阵以及直接服用的打造丹药，不能绕过整体替换。
6. 当前存在临时配置时，丹药和聚灵阵入口应提示将替换的词条数量；配置包含太古时增加确认，避免玩家无提示放弃高品质配置。

### 2.2 丹药服用规则

丹药按是否包含额外词条分为两类：

- **仅主词条**：`affixes.length == 1`。
  - 保留当前临时配置，只结算丹药主效果。
  - 主词条提供即时效果时，现有临时配置完全不变。
  - 主词条提供临时被动且与现有被动同 ID 时，只按新快照更新该 ID，不影响其他现有词条。
  - 主词条提供永久效果时，按永久效果正常生效，不清除任何临时或永久效果。
- **包含至少一条额外词条**：`affixes.length > 1`。
  - 成功服用后，以丹药的主词条和全部额外词条组成新配置，整体替换旧的非永久临时配置。
  - 主词条的即时效果、永久效果与临时效果按原有类型分别结算，只有临时配置参与整体替换。

丹药替换必须是原子操作：先确认可以使用并完成必要校验，再清除旧配置、应用新配置、重算属性和消耗物品。校验失败或服用被取消时不得清除旧配置。

后续若开放坐忘类丹药打造，可通过移除全部额外词条，把普通丹药加工为“保留现有临时配置”的仅主词条版本。

### 2.3 聚灵阵冥想轮数

| 聚灵阵发展度   | 普通冥想轮数 | 凝炼                                      |
| -------------- | -----------: | ----------------------------------------- |
| 无（rank 0）   |            1 | 无                                        |
| 凝气（rank 1） |            2 | 无                                        |
| 筑基（rank 2） |            3 | 无                                        |
| 结丹（rank 3） |            3 | 完成普通轮次后，可选择 1 条合格词条太古化 |
| 还婴（rank 4） |            3 | 同结丹，词条境界、等级与候选池继续提升    |
| 化神（rank 5） |            3 | 同结丹，词条境界、等级与候选池继续提升    |

轮数公式改为 `min(development + 1, 3)`。灵石成本、每次交互的时间消耗保持现规则，不因轮数上限调整而额外修改。

还婴、化神暂不通过增加轮数或凝炼条数成长，而通过词条境界、等级和候选池成长。首期每次完整冥想最多凝炼 1 条。

### 2.4 待生效配置、重复处理与提交

聚灵阵采用“先构建、后提交”的事务式流程：

1. 开始冥想后，本次获得的词条进入独立的待生效配置，不立即写入角色 `ephemeralPassives`，也不立即改变角色属性。
2. `_expArrayGrantedBuffs` 改为记录本次实际获得的词条 ID；`getExpArrayBuff` 接收排除列表，候选池先排除这些 ID。
3. `getExpArrayBuff` 成功时返回完整词条实例，由场景加入待生效配置，不再直接调用 `characterSetEphemeralPassive` 修改英雄。
4. 某类别在本次冥想中已无新词条可给时：
   - 返回空结果并提示玩家改选其他类别；
   - 不推进轮数；
   - 不消耗该次选文对应的游戏时间。
5. 本次冥想最多获得 3 条不同 ID 的临时词条。待生效界面同时展示当前描述与太古预览，但不把预览当作已生效属性。
6. 普通轮次及可选凝炼全部完成后，一次性清除旧的非永久临时被动，再将待生效配置写入角色并重算属性。
7. 冥想失败、点错颜色或中途取消时，只清理待生效配置和场景状态，旧配置保持不变。
8. 冥想重开、失败和完成时统一清理本次 ID 集合、待生效配置和凝炼候选状态。

### 2.5 结丹后的凝炼流程

普通轮次全部完成后，若发展度不低于 3：

1. 从本次待生效配置中收集带有合法 `greater` 配置且尚未太古的词条。
2. 进入独立“凝炼”阶段，展示这些词条的当前描述和太古后的预览。
3. 玩家选择 1 条进行太古化，或选择放弃并结束。
4. 没有合格候选时跳过凝炼，直接完成冥想，不强迫玩家进行无意义选择。
5. 凝炼完成后刷新待生效配置说明，再执行整体替换、完成提示和退出流程。

凝炼使用确定选择，不再叠加 5% 等额外随机概率。凝炼只修改本次待生效词条，不读取或修改旧配置中的同 ID 词条。

### 2.6 临时太古规则

- 只处理 `isEphemeral: true` 的临时被动，不处理永久属性、天赋或普通丹药主词条。
- 复用主计划的 `greater` 配置：
  - `greater.values` 控制指定数值的 `multiply/add/set`；
  - `greater.data` 只由明确实现消费逻辑的脚本读取；
  - 只有 `greater.description` 而没有数值或机制变化的词条不合法。
- 凝炼时将词条等级设为聚灵阵当前发展度对应境界的满级，再按普通被动公式和太古规则重算。
- 不写入 `isFreezed`，不引入打造锁定概念。
- `isGreater` 只表示品质与展示，不改变 `isPermanent`。
- 临时词条实例需要保留 `isGreater`、有效等级、最终数值与定制机制，确保生成、预览、整体替换和战斗使用同一份快照。

### 2.7 清除与生命周期

- 整体替换只清除 `isPermanent != true` 的临时被动。
- 战斗结束仍按现有 `clearEphemeralPassives` 规则清除非永久临时被动，临时太古也一并清除。
- 新的整体替换不会把临时效果转为永久，也不会改变已有永久效果。
- 普通丹药生成太古仍走主计划；本计划只负责这些词条在服用后如何组成配置和生效。

## 3. 代码修改范围

### 3.1 共享临时配置替换入口

涉及：

- `scripts/main/data/character/battle_entity.ht`
- 其他 `characterSetEphemeralPassive` 调用方

步骤：

1. 新增统一的临时配置替换函数，例如 `replaceEphemeralPassives(character, newPassives)`：
   - 只清除 `isPermanent != true` 的旧临时被动；
   - 写入完整新配置；
   - 最后统一调用 `characterCalculateStats`。
2. 保留单条临时被动写入能力供主词条例外使用，但各批次入口不得再分别实现一套覆盖逻辑。
3. 临时被动实例透传 `isGreater`、`greater`、`isPermanent`、有效等级和最终数值；普通与太古使用同一实例结构。
4. 审核所有 `characterSetEphemeralPassive` 调用方，将直接服用的打造丹药等入口纳入相同规则。
5. 战斗结束清除逻辑与整体替换共用“非永久”判定，避免两条路径对永久效果的解释不一致。

### 3.2 丹药服用流程

主要文件：`scripts/main/data/character/battle_entity.ht`

步骤：

1. `characterConsumePotion` 按 `item.affixes.length` 区分仅主词条与含额外词条丹药。
2. 仅主词条丹药直接结算主效果；若产生同 ID 临时被动，只更新该 ID，不清除其他临时配置。
3. 含额外词条丹药先组成完整新配置，再调用共享整体替换入口。
4. 保持 `overheal` 等即时主效果的原有处理，永久效果与临时效果分开结算。
5. 校验、替换、属性重算和消耗物品按成功路径一次完成，失败路径不清除旧配置。

### 3.3 聚灵阵场景流程

主要文件：`lib/scene/cultivation/cultivation.dart`

步骤：

1. 将 `_expArrayMaxRounds` 的计算改为最高 3 轮。
2. 将 `_expArrayGrantedBuffs` 改为本次已获得词条 ID 集合，新增本次待生效配置状态。
3. `_onExpArrayPhraseTap` 接收 `getExpArrayBuff` 的返回结果：
   - 成功时把实例加入待生效配置，记录 ID、推进轮数并消耗时间；
   - 类别耗尽时只提示，不推进轮数、不消耗时间。
4. 普通轮次完成后，在发展度不低于 3 时进入凝炼阶段；否则直接进入整体替换。
5. 凝炼阶段复用 `_meditatePhrases` 和选文布局，显示候选词条及太古预览，支持选择或放弃。
6. 完成时调用共享整体替换入口；失败、取消和重开只清理本次场景状态，不修改旧配置。
7. 更新被动说明时区分当前生效配置与本次待生效配置，不在每轮获得词条时直接重算英雄正式属性。

### 3.4 临时词条生成与凝炼

涉及：

- `scripts/main/binding/player.ht`
- `scripts/main/data/character/battle_entity.ht`

步骤：

1. `getExpArrayBuff(type, rank, {excludeIds})` 增加排除列表，成功时返回完整词条实例，类别耗尽时返回空结果，不再直接写入英雄。
2. 修正该函数注释中的类别说明，与实际的 `attack/defense/attribute/energy` 一致。
3. 凝炼函数改为处理待生效词条实例，例如 `upgradeExpArrayBuffToGreater(affix, rank)`：
   - 检查原词条存在合法 `greater` 配置；
   - 设置 `isGreater`、当前境界满级和最终数值；
   - 不设置 `isFreezed` 或 `isPermanent`。
4. 待生效实例保留 `greater` 配置，供预览、定制效果和整体替换使用。

### 3.5 数值与定制效果

涉及：

- `assets/data/passives.json5`
- 必要时 `scripts/main/cardgame/status_script.ht` 或其他对应消费脚本
- `lib/logic/logic.dart`（复用主计划的共享太古数值 helper）

步骤：

1. 为 `isEphemeral` 词条逐条配置或禁止 `greater`，优先处理伤害、护甲、属性和固定次数等明确数值。
2. 普通贡献与太古数值使用主计划的未取整贡献和最终取整规则，不在聚灵阵另建公式。
3. 纯机制词条只有存在明确 `greater.data` 消费方才允许凝炼；否则从候选中排除。
4. 不统一缩放阈值、费用、资源、百分比或全部机制字段。

### 3.6 展示、本地化、校验与文档

涉及：

- `lib/data/game.dart`
- `assets/locale/zh/site.json`
- `utils/data_validate/game_data_validate.dart`
- `docs/docs/how2play/rpg/item/consumable/readme.md`
- `docs/docs/how2play/rpg/cultivation/readme.md`
- `plan/battle_system_overview.md`

步骤：

1. `_getPassivesDescription` 在临时太古词条前复用 `kAffixLeading2 = '✶'`，并将整行设为黄色；普通临时被动保持原样式。
2. 凝炼候选同时显示当前描述与太古预览，明确本次只能选一条。
3. 增加整体替换、仅主词条保留、替换确认、凝炼、放弃、成功、无候选和类别耗尽等本地化文本。
4. 与主计划共用 `greater` 结构校验，只有描述没有实际效果的词条不得进入凝炼候选。
5. 丹药文档补充整体替换、仅主词条例外和生成太亘古径；修炼文档补充轮数、待生效配置、失败保留、凝炼与战后清除规则。
6. 总览更新临时配置来源、整体替换、展示和清除路径。

## 4. 分阶段实施顺序

### 阶段一：共享替换与丹药规则

1. 实现非永久临时配置整体替换入口。
2. 接入丹药含额外词条时整体替换、仅主词条时保留配置的例外。
3. 审核直接服用的打造丹药等全部临时被动入口。
4. 先完成替换、永久保留和失败不清除测试。

### 阶段二：聚灵阵轮数与事务式流程

1. 轮数封顶为 3，完成同次 ID 排除与类别耗尽处理。
2. `getExpArrayBuff` 返回实例，场景改为构建待生效配置。
3. 实现成功提交、失败/取消保留旧配置和待生效预览。

### 阶段三：临时太古

1. 复用主计划被动太古数值 helper。
2. 为临时词条配置 `greater`，实现待生效实例的单条凝炼。
3. 完成结丹后的候选选择、放弃流程、`✶` 黄色展示及本地化。

### 阶段四：验证与文档

1. 完成数据校验、单元测试和脚本编译。
2. 验证丹药、聚灵阵、永久效果和战斗结束清除的完整链路。
3. 同步玩法文档与系统总览。

## 5. 测试计划

项目已有测试，可新增 `test/exp_array_test.dart`，并复用现有 Hetu 测试方式。

### 丹药与整体替换

- 含额外词条的丹药成功服用后，旧非永久临时配置全部移除，新主词条与额外词条完整生效。
- 仅主词条丹药不清除现有配置；即时主效果不改变临时配置，同 ID 临时主效果只更新该 ID。
- 永久被动和已经转为永久的效果在整体替换中保留。
- 普通新配置可以替换包含太古的旧配置，入口有明确提示与确认。
- 校验失败或取消服用时，旧配置和物品均保持不变。
- 直接服用的打造丹药等入口遵守相同的批次替换规则。

### 轮数、待生效配置与提交

- development 0～5 的轮数分别为 1、2、3、3、3、3。
- 同一次冥想不会获得重复 ID。
- 类别耗尽时不推进轮数、不消耗时间，可选择其他类别。
- 灵石成本、词条 rank 和等级区间保持原规则。
- 冥想过程中词条只进入待生效配置，不改变英雄正式属性。
- 冥想失败或取消时旧配置保留；成功完成后才整体替换，不出现新旧批次叠加。

### 凝炼

- development 0～2 不开放凝炼，development 3～5 在普通轮次后开放。
- 每次完整冥想最多凝炼 1 条，可以放弃。
- 无 `greater` 配置、只有描述或无消费方的词条不会进入候选。
- 凝炼后等级为当前境界满级，数值只按配置变化一次。
- 凝炼修改的是本次待生效实例，不影响旧配置中的同 ID 词条。

### 展示与生命周期

- 临时太古在被动说明中显示 `✶` 和黄色文本。
- 当前生效配置与待生效配置在界面和属性计算上明确区分。
- 战斗开始时替换后的新配置正常参与属性聚合。
- 战斗结束后临时太古与其他非永久临时被动一起清除，永久效果保留。
- 普通丹药、装备和卡牌的生成太亘古径仍遵循主计划，不被本流程改写。

## 6. 验证命令与人工验收

执行：

```bash
dart run utils/data_validate/game_data_validate.dart

```

`python build.py` 若遇 Windows 下 Hetu PATH 问题，按项目说明使用 dart install 的 `hetu.bat` 绝对路径。

人工验收：

1. 在已有临时配置时分别服用仅主词条丹药和含额外词条丹药，确认保留与替换行为及提示。
2. 使用含永久效果的丹药或打造丹药，确认永久效果在后续整体替换中保留。
3. 分别使用 development 0～5 的聚灵阵完成冥想，确认轮数、待生效配置和候选池。
4. 在同一冥想中重复选择同类别，确认不会浪费轮次或重复词条。
5. 在结丹以上聚灵阵完成 3 轮，选择、预览并确认 1 条临时太古。
6. 分别验证冥想成功、失败和取消，确认只有成功才替换旧配置。
7. 用普通新配置替换包含太古的旧配置，确认提示清楚且没有新旧效果叠加。
8. 完成一场战斗，确认临时太古正常生效并在战后清除，永久效果保留。

## 7. 完成标准

- 含额外词条的丹药与成功完成的聚灵阵均以新配置整体替换旧的非永久临时配置。
- 仅主词条丹药保留现有配置，只结算主效果；永久效果不被任何替换流程清除。
- 聚灵阵使用待生效配置，只有成功才提交，失败或取消不影响旧配置。
- 聚灵阵每次冥想最多 3 轮、3 条不同 ID 的新临时词条，类别耗尽不耗时、不推进轮数。
- 结丹后每次完整冥想可由玩家主动凝炼最多 1 条临时太古。
- 聚灵阵提供定向选择临时太古的途径，临时太古展示统一为 `✶` 黄色并在战斗后正常清除。
- 普通丹药、装备、卡牌的生成规则未被本计划修改。
- 数据校验、静态分析、脚本编译及完整测试通过，相关文档与本地化已同步。
