# UI 架构与商业化整合计划

> 状态：方向性规划。当前优先跑通 Demo 核心循环，不进行全面 UI 重写。
>
> 已完成一项局部优化：`HoverInfo` 自行监听浮窗状态，`GameUIOverlay` 不再因浮窗显示、隐藏或详细模式切换而整体重建。

## 1. 总体方向

保留 Flutter + Flame 的混合架构，不以“统一框架”为目标重写现有界面。

- Flame 负责场景、角色、卡牌、空间布局、战斗和与场景生命周期绑定的交互。
- Flutter 负责背包、装备、商店、设置、存档、复杂文本、滚动列表和通用面板。
- 混合场景由 Flame 的场景表现与 Flutter 的复杂控件共同组成。
- 商业化 UI 的首要目标是视觉一致、输入可靠、反馈清楚和显示适配，而不是底层完全自研。

## 2. 主题与共享组件

现有 `GameUI`、Material 主题、Fluent 主题和共享样式继续作为基础。

- 建立统一的颜色、字体、字号、间距、边框、图标、状态和动画规范。
- 逐步形成项目内的 Game UI 组件层，统一按钮、面板、对话框、菜单、标签页、提示和滚动区域的观感与行为。
- Flutter 与 Flame 组件共享同一套视觉规范和资源约定。
- 移除不表达状态或操作结果的动画，保留短而明确的交互反馈及必要的场景演出。
- 逐步收拢 Fluent UI 的直接使用，避免同时扩展多套主题和交互规则。
- 暂不自研完整 UI 底层库；只有现有框架持续阻碍关键交互时才重新评估。

## 3. 界面场景化

是否场景化由玩法和表现收益决定，而不是由当前界面使用对话框还是全屏页面决定。

- 卡牌库是现有混合场景参考：Flame 负责卡牌和场景交互，Flutter 负责物品栏与材料选择。
- 工坊可在后续表现整合中优先转为混合场景，保留 Flutter 的背包、材料和词条说明，Flame 负责操作台、装备槽和打造演出。
- 炼丹只有在增加配比、火候、过程操作或场景演出后才考虑提高 Flame 比例。
- 任务详情和任务列表继续以 Flutter 为主。
- 全屏化不等于必须使用 Flame，纯 Flutter 的全屏功能界面仍是合法方案。

## 4. 分辨率、窗口与全屏

Demo 当前继续使用固定 1440×810，不开放自由调整窗口大小。

后续显示方案采用可选分辨率档位；窗口化时，所选分辨率就是窗口大小。切换分辨率时需要重新计算并应用 UI 布局，全屏模式复用相同的显示与布局流程。

- 优先提供相同宽高比的档位，减少额外布局分支。
- 明确区分实际窗口尺寸、逻辑尺寸和 Flame 摄像机尺寸。
- `GameUI` 保留共享视觉规范，逐步不再集中保存所有场景的位置公式。
- 复杂场景由各自的布局对象负责空间结构，场景在尺寸变化时重新布局已有组件，不重新生成游戏内容。
- 分辨率和全屏切换优先限制在主菜单或其他安全界面，避免战斗和模态流程中的状态丢失。
- 设置最小可读的窗口尺寸，并检查高 DPI、文本可读性、鼠标坐标、Hover 和拖拽行为。

## 5. 浮窗统一

长期方向是统一使用 Flutter 的 `HoverContent` / `HoverInfo` 表达项目浮窗，Flame 的 `Hovertip` 不再继续扩展。

统一前需要保证：

- 浮窗状态更新只重建浮窗子树，而不是整个 Overlay。
- 浮窗与显示目标具有明确的所有者关系，旧目标的退出事件不能误关新目标的浮窗。
- Flame 目标通过统一适配层转换到 Flutter 坐标，调用方不自行处理摄像机、逻辑画布和留边差异。
- 场景退出、模态打开和其他交互切换具有统一清理规则。
- 浮窗支持富文本、任意 Widget、详细模式和合理的屏幕边界与最大尺寸。

迁移应按场景逐步进行，不在 Demo 核心流程尚未验证时一次性替换全部调用。

## 6. GameUIOverlay 演进

保留 `GameUIOverlay` 作为场景统一的 Flutter 挂载点和层级组合入口，但逐步降低其业务耦合。

- Overlay 主要管理层级、场景可见性和组合关系。
- 商店、战前准备、物品选择、打造、奖励和浮窗等功能逐步由独立子组件监听自身状态。
- 避免在 Overlay 构建过程中保存可以由 Provider 直接推导的临时状态。
- 面板增加构建注册机制可作为后续选项，避免持续扩大集中式类型分派。
- 不以拆成多个互不协调的 Overlay 为目标，也不为追求文件数量而过度拆分。

## 7. 推荐节奏

### 当前 Demo 阶段

- 保持固定分辨率和现有界面结构。
- 不进行全面主题、场景或浮窗迁移。
- 新增界面尽量遵循现有职责边界，避免继续扩大集中式布局与状态管理。

### Demo 核心循环完成后的整合阶段

- 统一主题、共享组件和交互动画。
- 拆分场景布局，加入固定分辨率选项与安全切换流程。
- 优化 Overlay 的状态隔离，并逐步统一浮窗。
- 根据实际表现收益决定是否将工坊改为混合场景。
- 在发布构建上检查性能、输入、DPI、全屏和文本可读性。

### 商业化发布前

- 完成目标分辨率和显示模式的覆盖检查。
- 检查窗口切换、场景切换、模态叠加和输入焦点的一致性。
- 确认第三方 UI、字体、图片和其他资源的商业使用许可。

## 8. 范围边界

本计划不要求：

- 为追求架构纯粹而重写全部 UI；
- 从零实现完整 UI 框架；
- 将所有界面迁移为纯 Flame；
- 在 Demo 中开放自由窗口缩放；
- 让 UI 重构阻塞战斗、秘境、成长和跨轮循环的验证。
